# V1 제거 준비 점검

점검 기준: 2026-09-09, `issue/28-learning-system-v2` 브랜치와 구현 계약 「콘텐츠 ver.1–ver.2 병렬 운영과 안전한 제거 계약」.

## 결론

V2 기능과 저장소는 독립 실행에 필요한 주 경로를 갖췄지만, **V1 코드와 에셋을 바로 완전 삭제할 단계는 아니다.** 구현 계약은 V1 진입점 제거와 V1 전용 코드·에셋 삭제 사이에 최소 한 번의 안정화 릴리스를 요구한다. 현재 저장소에는 V1 기록 열람·내보내기, 오래된 링크 처리, 종료 안내, 복구 가능한 고정 기준점도 아직 없다.

따라서 다음 작업은 한 번에 삭제하는 PR보다 아래 두 단계로 나누는 것이 안전하다.

1. V1 진입을 종료하되 기록 읽기·내보내기와 복구 수단을 남기는 안정화 릴리스
2. 안정화 확인 뒤 V1 전용 구현·에셋과 호환 분기를 삭제하는 릴리스

## 확인된 준비 상태

- [x] 신규 사용자의 기본 선택은 V2다.
- [x] V2 manifest, 학습 페이지, 지식 카탈로그가 `Resources/Content`에 독립적으로 존재한다.
- [x] V2 홈, 학습, 지식 책장 라우트가 존재한다.
- [x] V2 진행 기록은 `ConriculumCurrent` SwiftData 컨테이너에 저장되고 V1 컨테이너와 스키마가 분리되어 있다.
- [x] 기존 `learning.progress.v2` 기록은 원본을 지우지 않고 현재 저장소로 가져온다.
- [x] V1 전용 소스와 리소스의 주 경계는 각 레이어의 `V1/` 폴더로 이동했다.
- [x] V1과 V2를 함께 포함한 전체 macOS 테스트가 통과한다.
- [x] 원격 `release/ver-1` 브랜치가 제거 전 V1 기준 코드 `18558eb`을 가리킨다.
- [x] 앱 코드에는 V1 저장 데이터를 삭제하는 경로가 없다.

`release/ver-1`은 이동 가능한 브랜치이므로 복구 계약의 최종 산출물은 아니다. 삭제 착수 전 해당 커밋을 가리키는 보호된 태그와 재현 가능한 빌드·콘텐츠 번들이 별도로 필요하다.

## 삭제 전에 완료해야 하는 제품 조건

### 1. V1 기록을 읽을 수 있는 보관 경로

현재 V1 SwiftData는 보존되지만 V1 코드를 삭제하면 앱에서 읽거나 내보낼 방법도 함께 사라진다. 다음 중 하나를 먼저 구현하고 실제 기존 DB로 검증해야 한다.

- 읽기 전용 `archivedV1Progress` 화면과 최소 V1 레코드 리더 유지
- 또는 사용자 요청으로 파일을 생성하는 V1 진행 내보내기

V1 기록을 V2 완료 기록으로 자동 변환하면 안 된다. 두 과정의 완료 증거가 다르며, 저장 데이터 삭제 역시 별도 동의나 보존 정책 없이는 실행하지 않는다.

### 2. V1 선택과 오래된 링크의 종료 처리

- 저장된 `learning.content.selected-version == v1`은 첫 실행에서 V2로 안전하게 전환해야 한다.
- 지원 중인 V1 딥 링크·북마크 목록을 확정해야 한다.
- 대응 가능한 링크는 V2 페이지로 안내하고, 대응표가 없는 링크는 “종료된 과정” 설명과 홈 이동을 제공해야 한다.
- 전환 실패 시 사용자가 이해할 수 있는 복구 문구가 필요하다.

현재 앱에는 URL/deep-link 처리기가 없으므로 “지원하는 링크가 없음”을 제품 결정으로 명시하거나 종료 라우트를 구현해야 한다.

### 3. 종료 안내와 안정화 기간

- V1 선택기를 제거하기 전에 종료 안내와 지원 문구를 확정한다.
- V1 진입점만 제거한 빌드를 먼저 배포한다.
- 최소 한 번의 안정화 기간 동안 V2 홈→학습→지식→복원과 V1 보관 기록을 관찰한다.
- 긴급 롤백 필요가 없음을 확인한 뒤에만 V1 코드·에셋 삭제를 진행한다.

### 4. 복구 가능한 기준점

- `18558eb` 또는 승인된 마지막 V1 커밋에 보호된 태그를 만든다.
- 해당 소스에서 재현 가능한 앱 빌드와 V1 콘텐츠 번들을 보관한다.
- 저장 스키마와 콘텐츠 ID 인벤토리를 태그와 함께 보관한다.

## 완전 삭제 PR에서 함께 정리해야 하는 코드 경계

`V1/` 폴더만 삭제하면 빌드되지 않는다. 현재 버전 폴더 밖에도 V1을 조립하거나 V1 타입을 공유하는 코드가 남아 있다.

### 앱 조립과 라우팅

- `AppAssembly`가 아직 V1 SwiftData 컨테이너와 네 V1 클라이언트로 앱을 시작한다.
- `ConriculumApp`이 V1 의존성을 주입하고 V1 컨테이너를 SwiftUI 환경에 제공한다.
- `AppFeature`와 `AppView`가 V1 workspace 상태·라우트·화면을 소유한다.
- 완전 삭제 시 앱 루트는 현재 Persistence 환경만으로 시작할 수 있어야 한다.

### 홈과 버전 선택

- `HomeFeature`는 실행 때 V1 홈 데이터도 함께 읽고 V1 진입 액션을 유지한다.
- `HomeView`에는 “ver.1 기존 과정 보기” 버튼과 V1 홈 전체 표현이 남아 있다.
- `ContentVersion.v1`과 V1 선택 복원 테스트를 제거하기 전에 저장된 V1 선택을 V2로 전환하는 호환 처리가 필요하다.

### 지식 화면과 공용 UI

- `KnowledgeSystemFeature`는 V1/V2 로딩 분기와 V1 학습 라우트를 함께 소유한다.
- `KnowledgeSystemView`의 Preview가 V1 번들 리소스를 사용한다.
- `LearnedKnowledgeResolver`는 V1 전용이지만 아직 `Features/KnowledgeSystem` 바깥 경계에 있다.
- `KnowledgeChangeCollection`은 V1 개인화 검토 타입을 참조한다.
- `LearningComponentChrome` 일부 컴포넌트는 V1 콘텐츠 타입을 참조하므로 V1 전용 부분을 함께 삭제하고, V2가 실제로 쓰는 공용 부분만 남겨야 한다.
- 공용 `ContentResourceDecoder`의 V1 전용 오류 변환 분기를 제거해야 한다.

### 전용 소스·에셋·테스트

아래 폴더는 V1 전용 소유권으로 확인되었다.

- `Conriculum/Content/V1`
- `Conriculum/Dependencies/V1`
- `Conriculum/Domain/V1`
- `Conriculum/Features/V1`
- `Conriculum/Persistence/V1`
- `Conriculum/Resources/V1`
- `ConriculumTests` 아래의 모든 `V1/` 폴더
- `Documentation/Persistence/V1`

버전 폴더 밖의 App, Home, KnowledgeSystem 회귀 테스트도 V1 시나리오와 V2 시나리오가 섞여 있으므로 파일을 통째로 지우지 말고 V2 수용 조건을 남긴다.

## 삭제 전 마지막 검증 행렬

- [ ] clean install에서 V2 홈과 첫 학습 페이지가 열린다.
- [ ] V1 선택과 V1 DB가 있는 업데이트 설치에서 V2 전환 및 V1 기록 열람·내보내기가 동작한다.
- [ ] 앱 재실행 뒤 V2 마지막 위치, 완료 증거, 게임 응답, 도움 수준이 복원된다.
- [ ] 오프라인에서 V2 학습 JSON·지식 카탈로그·용어 도움을 사용할 수 있다.
- [ ] 손상된 V2 페이지가 다른 페이지와 보관 기록 접근을 막지 않는다.
- [ ] 키보드와 VoiceOver로 Stage 1 단일·복수 선택, 연결 활동과 Stage 2 학습을 완료할 수 있다.
- [ ] V1 선택기 제거 뒤에도 V1 저장 파일이 삭제·덮어쓰기 되지 않는다.
- [ ] V1 코드·에셋 삭제 뒤 V2 전체 테스트와 빌드가 통과한다.

## 다음 이슈의 완료 조건

완전 삭제 이슈를 시작할 때는 위 제품 조건 1–4의 담당자·산출물·검증 결과를 이슈 본문에 연결한다. 안정화 기간을 이미 충족했다면 완전 삭제 범위를 진행할 수 있다. 충족하지 않았다면 다음 이슈는 “V1 진입 종료와 보관”까지만 수행하고, 실제 소스·에셋 삭제는 후속 이슈로 분리한다.
