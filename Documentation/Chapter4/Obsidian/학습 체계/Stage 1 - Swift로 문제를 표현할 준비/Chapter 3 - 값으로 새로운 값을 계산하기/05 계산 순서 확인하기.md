# 계산 순서 확인하기

> 페이지 목표: 연산자 우선순위와 괄호가 표현식의 평가 순서와 결과를 어떻게 바꾸는지 설명한다.

## 방향잡기

[학습 나침반]

- 이전 연결: 4페이지에서 큰 계산을 의미 있는 단계로 나눴다. 한 단계에 여러 연산이 남으면 어느 연산을 먼저 평가할지 읽어야 한다.
- 핵심 질문: 이 표현식은 어디부터 하나의 값으로 접히며, 괄호는 그 순서를 어떻게 바꿀까?
- 첫 예상: `18_000 * 4 + 3_000`과 `(18_000 + 3_000) * 4`의 첫 연산과 결과를 적는다.
- 초기 확신: 낮음 | 중간 | 높음과 그 이유를 남긴다.
- 완료 증거: 여러 연산이 있는 식의 평가 순서를 표시하고 괄호가 필요한 의도를 설명한다.

## 탐색

[상황 제시]

- 제목: 같은 숫자와 기호, 다른 결과
- 상황: 곱셈과 덧셈의 순서가 바뀌면 배송비를 한 번 더하는 계산과 사람마다 더하는 계산이 달라진다.
- 자료: `18_000 * 4 + 3_000` | `(18_000 + 3_000) * 4`
- 첫 질문: 괄호가 없을 때 왼쪽 기호부터 무조건 계산하는가?

[개념 대조]

- 비교 기준: 기본 우선순위 | 괄호로 드러낸 의도
- 항목: `*`와 `/`는 `+`와 `-`보다 먼저 평가한다 | 같은 우선순위는 왼쪽에서 오른쪽으로 평가한다 | 괄호 안 표현식은 먼저 하나의 값이 된다 | 괄호는 계산 의도와 경계를 눈에 보이게 한다
- 관찰 질문: 결과만 계산하지 않고 각 단계의 중간 결과를 쓸 수 있는가?

[판단 기준]

- 기준 질문: 괄호가 있는가? 어떤 연산자의 우선순위가 높은가? 같은 우선순위라면 어느 쪽이 먼저인가? 문제의 관계와 실제 순서가 일치하는가?
- 적용 순서: 괄호 표시 → 우선순위 표시 → 첫 연산 결과 → 남은 식 → 최종 결과
- 주의점: 우선순위를 알고 있어도 사람에게 계산 의도를 분명히 보여 줘야 할 때 괄호나 중간값을 사용할 수 있다.

## 적용

[지식 연결]

- 지식 링크: [[지식 체계/03 표현식과 연산/계산 순서|계산 순서]], [[지식 체계/03 표현식과 연산/표현식|표현식]], [[지식 체계/03 표현식과 연산/중간값|중간값]]
- 이 페이지에서의 쓰임: 표현식을 작은 결과값으로 차례로 접고 문제의 관계와 평가 순서를 대조한다.
- 표시 시점: 첫 예상 뒤 펼친다.

[빈칸 완성]

- 시작 내용: `18_000 * 4 + 3_000 → ____ + 3_000 → ____`
- 빈칸: 첫 연산 결과 | 최종 결과 | 괄호를 넣으면 먼저 달라질 부분
- 선택 항목: `72_000` | `75_000` | `21_000` | `84_000` | `18_000 + 3_000`
- 완료 조건: 두 표현식의 단계별 결과를 완성하고 서로 다른 문제 관계를 한 문장씩 적는다.

[선택 후 설명]

- 질문: 책 네 권 가격에 배송비를 한 번만 더하려면 어떤 식이 의도와 맞는가?
- 선택지: `bookPrice * participantCount + deliveryFee` | `(bookPrice + deliveryFee) * participantCount`
- 이유 입력: 배송비가 몇 번 반영되는지 평가 순서로 설명한다.
- 판단 피드백: 최종 숫자만 비교하지 말고 괄호 안 결과가 무엇을 뜻하는지 이름 붙인다.

## 성찰

[학습 마무리]

- 첫 예상: 두 식의 최초 계산 순서와 결과
- 최종 설명: 괄호·우선순위·중간 결과를 사용해 두 식의 차이를 설명한다.
- 확신 변화: 다시 고른 확신과 영향을 준 근거를 적는다.
- 바뀐 기준: 왼쪽부터 읽기보다 표현식을 결과값 단위로 접는 기준을 사용했는지 적는다.
- 다음에 쓸 장소: 같은 `/` 표현식도 `Int`와 `Double`에서 결과가 어떻게 달라지는지 비교한다.
- 확인 질문: 문제 의도와 표현식의 실제 평가 순서가 일치하는지 확인할 수 있는가?
- 필요한 증거: 첫 연산, 중간 결과, 최종 결과, 괄호 의도
- 다시 시도 조건: 왼쪽 기호부터 계산했다면 괄호와 연산자 종류를 먼저 표시한다.

## 선택 학습과 개인 지식화

[확장 과제]

- 제목: 우선순위를 알아도 괄호 쓰기
- 안내: `bookPrice * participantCount + deliveryFee`에 의미 단위를 드러내는 괄호를 선택적으로 넣는다.
- 추가 자료: `(bookPrice * participantCount) + deliveryFee`
- 추가 활동: 결과는 같지만 읽기 쉬워지는 이유와 불필요한 괄호의 경계를 설명한다.
- 연결 지식: [[지식 체계/03 표현식과 연산/중간값|중간값]]

[개인 지식 반영]

- 근거 활동: `[빈칸 완성]`의 단계 결과와 `[학습 마무리]`의 확인 기준
- 연결 지식: [[지식 체계/03 표현식과 연산/계산 순서|계산 순서]]
- 후보 유형: 계산 순서를 읽는 나의 체크리스트
- 편집 가능한 초안: `괄호를 먼저 찾고, 곱셈·나눗셈을 덧셈·뺄셈보다 먼저 하나의 값으로 접은 뒤 문제의 관계와 비교한다.`
- 확인 질문: 이 체크리스트를 나의 표현으로 남길까?
- 저장 항목: 나의 설명, 순서 예시, 근거 활동 ID, 수정 시각
- 취소 결과: 학습 응답은 유지하고 개인 지식은 변경하지 않는다.
