# 표현식의 결과 예상하기

> 페이지 목표: 표현식이 값과 연산을 평가해 하나의 결과값이 되는 과정을 실행 전에 추적한다.

## 방향잡기

[학습 나침반]

- 이전 연결: 1페이지에서 입력과 결과 사이의 관계를 화살표로 만들었다. 이제 관계 하나를 Swift가 평가할 표현식으로 읽는다.
- 핵심 질문: 이 표현식을 평가하면 어떤 값이 어떤 순서로 하나의 결과가 될까?
- 첫 예상: `4 * 18_000`과 `72_000 + 3_000`의 결과와 역할을 실행하지 않고 적는다.
- 초기 확신: 낮음 | 중간 | 높음과 이유를 남긴다.
- 완료 증거: 표현식의 입력값·연산·결과값을 표시하고 식별자를 사용한 식의 결과를 예상한다.

## 탐색

[상황 제시]

- 제목: 결과가 되기 전의 코드
- 상황: Swift는 표현식을 평가해 하나의 값으로 만든 뒤 그 값을 이름에 저장할 수 있다.
- 자료: `participantCount * bookPrice` | `bookSubtotal + deliveryFee` | `totalCost`
- 첫 질문: 세 조각 중 그 자체로 계산되는 표현식과 결과를 가리키는 이름은 무엇인가?

[개념 대조]

- 비교 기준: 이미 준비된 값 | 평가해서 새 값을 만드는 표현식
- 항목: `participantCount`는 값의 이름 | `4`는 리터럴 | `participantCount * bookPrice`는 두 값을 곱해 결과를 만드는 표현식 | `let bookSubtotal = ...`은 결과에 이름을 붙이는 선언
- 관찰 질문: 표현식 전체를 하나의 결과값으로 바꿔 읽을 수 있는가?

[개념 정의]

- 개념: 표현식과 평가
- 한 문장 정의: 표현식은 값과 연산을 조합한 코드고, 평가는 그 표현식을 계산해 하나의 결과값을 얻는 과정이다.
- 적용 범위: `4 * 18_000 → 72_000`, `72_000 + 3_000 → 75_000`
- 지식 링크: [[지식 체계/03 표현식과 연산/표현식|표현식]]

## 적용

[지식 연결]

- 지식 링크: [[지식 체계/03 표현식과 연산/표현식|표현식]], [[지식 체계/02 값과 타입/값|값]]
- 이 페이지에서의 쓰임: 표현식의 각 이름을 현재 값으로 바꿔 보고 연산 뒤 결과 하나로 접는다.
- 표시 시점: 첫 결과 예상 뒤 펼친다.

[대응 연결]

- 왼쪽 항목: `participantCount * bookPrice` | `bookSubtotal + deliveryFee` | `let totalCost = ...`
- 오른쪽 항목: `72_000` | `75_000` | 계산 결과에 이름 붙이기
- 연결 규칙: 표현식을 입력값으로 치환하고 평가 결과 또는 선언의 역할에 연결한다.
- 완료 조건: 세 항목을 연결하고 첫 번째 결과가 두 번째 표현식의 입력이 되는 흐름을 설명한다.

[자유 작성]

- 과제: `let totalCost = bookSubtotal + deliveryFee`를 실행 순서가 보이게 설명한다.
- 입력 형식: `이름을 값으로 읽기 → 연산하기 → 결과값 → 이름에 저장하기`
- 필수 근거: `bookSubtotal`과 `deliveryFee`의 현재 값을 포함한다.
- 제출 뒤 예시: `72_000과 3_000을 더해 75_000을 만들고 totalCost라는 이름에 저장한다.`

## 성찰

[학습 마무리]

- 첫 예상: 두 표현식의 최초 예상 결과
- 최종 설명: 표현식·평가·결과값을 구분해 설명한다.
- 확신 변화: 다시 고른 확신과 영향을 준 근거를 적는다.
- 바뀐 기준: 코드를 기호 묶음으로 보던 방식에서 결과값으로 접어 읽는 방식으로 무엇이 달라졌는지 적는다.
- 다음에 쓸 장소: 자연어 관계에 맞는 산술 연산자를 선택한다.
- 확인 질문: 식별자가 포함된 표현식의 결과를 실행 전에 추적할 수 있는가?
- 필요한 증거: 입력값 치환, 연산, 예상 결과, 선언의 역할
- 다시 시도 조건: 선언 전체와 표현식을 구분하지 못했다면 `=` 오른쪽만 먼저 하나의 값으로 평가한다.
