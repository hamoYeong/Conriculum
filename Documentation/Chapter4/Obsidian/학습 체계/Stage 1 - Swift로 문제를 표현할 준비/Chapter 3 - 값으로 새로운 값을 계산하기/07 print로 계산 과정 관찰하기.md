# print로 계산 과정 관찰하기

> 페이지 목표: 실행 전 예상한 중간값과 최종값을 `print`로 관찰하고 처음 달라진 계산 단계를 찾는다.

## 방향잡기

[학습 나침반]

- 이전 연결: 1~6페이지에서 입력·연산·순서·타입을 사용해 결과를 실행 전에 예상했다. 이제 실행은 예상의 답을 대신하는 것이 아니라 비교할 증거가 된다.
- 핵심 질문: 무엇을 어느 지점에서 출력해야 계산 흐름이 예상과 달라진 첫 단계를 찾을 수 있을까?
- 첫 예상: `bookSubtotal`과 `totalCost`의 값을 먼저 적고 어느 값을 print할지 고른다.
- 초기 확신: 낮음 | 중간 | 높음과 이유를 남긴다.
- 완료 증거: 중간값과 최종값의 예상·실제 결과를 비교하고 차이가 시작된 입력 또는 표현식을 설명한다.

## 탐색

[상황 제시]

- 제목: 마지막 숫자 하나만 보면 놓치는 것
- 상황: 예상은 `75_000`인데 실행 결과가 다르다. 최종값만 출력하면 어느 단계부터 달라졌는지 알기 어렵다.
- 자료:

```swift
let bookSubtotal = participantCount * bookPrice
let totalCost = bookSubtotal + deliveryFee
```

- 첫 질문: 두 계산 중 첫 번째가 예상과 다른지 확인하려면 어느 이름을 먼저 관찰해야 하는가?

[개념 대조]

- 비교 기준: print가 결과를 만든다 | print가 이미 계산된 값을 보여 준다
- 항목: 표현식과 선언이 값을 만든다 | `print(bookSubtotal)`은 중간값을 관찰한다 | `print(totalCost)`는 최종값을 관찰한다 | 관찰 위치는 문제를 찾을 범위를 좁힌다
- 관찰 질문: print 줄을 지워도 계산된 값 자체는 같은가?

[과정 안내]

- 단계: 실행 전 예상 기록 → 가장 이른 중간값 출력 → 실제와 비교 → 같으면 다음 값 출력 → 처음 다른 단계의 입력과 식 확인
- 단계별 질문: 무엇이 나와야 하는가? | 실제로 무엇이 나왔는가? | 처음 달라진 값은 무엇인가? | 그 값을 만든 입력과 식은 무엇인가?
- 완료 모습: `예상 → 실제 → 첫 차이 → 확인할 입력·표현식` 기록을 남긴다.

## 적용

[지식 연결]

- 지식 링크: [[지식 체계/03 표현식과 연산/print로 관찰하기|print로 관찰하기]], [[지식 체계/03 표현식과 연산/중간값|중간값]], [[지식 체계/04 실행 흐름/00 분류 안내|실행 흐름]]
- 이 페이지에서의 쓰임: 결과를 추측으로 바꾸지 않고 자신의 예상과 실제 실행을 단계별로 비교한다.
- 표시 시점: 관찰 지점을 고른 뒤 펼친다.

[코드 조립]

- 시작 코드:

```swift
let bookSubtotal = participantCount * bookPrice
____
let totalCost = bookSubtotal + deliveryFee
____
```

- 조각: `print(bookSubtotal)` | `print(totalCost)` | `print(participantCount)` | `print(deliveryFee)`
- 고정 부분: 계산 순서는 바꾸지 않고 중간값과 최종값 뒤에 관찰 지점을 둔다.
- 완료 조건: 두 print를 배치하고 각 줄에 예상값과 그 값을 먼저 보는 이유를 적는다.

[자유 작성]

- 과제: `bookSubtotal`은 예상과 같고 `totalCost`만 다를 때 다음에 확인할 값과 표현식을 설명한다.
- 입력 형식: `같은 값 → 처음 다른 값 → 확인할 입력 → 확인할 표현식`
- 필수 근거: `deliveryFee`와 덧셈 표현식을 포함한다.
- 제출 뒤 예시: `bookSubtotal은 같음 → totalCost가 다름 → deliveryFee 확인 → bookSubtotal + deliveryFee 확인`

## 성찰

[학습 마무리]

- 첫 예상: 중간값·최종값 예상과 처음 고른 관찰 지점
- 최종 설명: 예상·실제·첫 차이와 확인할 입력·표현식
- 확신 변화: 다시 고른 확신과 영향을 준 관찰 근거를 적는다.
- 바뀐 기준: 마지막 결과만 보는 대신 가장 이른 중간값부터 비교하게 되었는지 적는다.
- 다음에 쓸 장소: 새로운 문제에서 관계부터 관찰까지 전체 계산 흐름을 혼자 만든다.
- 확인 질문: print를 계산과 구분하고 오류 범위를 좁히는 관찰 지점으로 사용할 수 있는가?
- 필요한 증거: 실행 전 예상, print 위치, 실제 결과, 첫 차이, 원인 후보
- 다시 시도 조건: 실제 결과를 먼저 봤다면 코드를 바꾼 뒤 새 예상부터 기록한다.
