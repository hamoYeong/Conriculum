# 큰 계산을 중간값으로 나누기

> 페이지 목표: 여러 관계가 섞인 계산을 의미가 드러나는 중간값으로 나누고 단계 사이의 흐름을 설명한다.

## 방향잡기

[학습 나침반]

- 이전 연결: 3페이지에서 관계 하나에 맞는 산술 연산을 선택했다. 이제 두 관계가 이어지는 계산을 읽기 쉬운 단계로 나눈다.
- 핵심 질문: 어떤 계산 결과에 이름을 붙이면 큰 식의 책임과 오류 위치가 더 잘 보일까?
- 첫 예상: `participantCount * bookPrice + deliveryFee`를 어디서 나눌지 표시하고 중간값 이름을 붙인다.
- 초기 확신: 낮음 | 중간 | 높음과 이유를 적는다.
- 완료 증거: 큰 계산을 두 단계 이상으로 나누고 중간값의 의미·입력·다음 사용을 설명한다.

## 탐색

[상황 제시]

- 제목: 한 줄의 정답과 두 단계의 설명
- 상황: 두 코드는 같은 전체 비용을 만들지만, 하나는 계산 관계가 한 줄에 겹치고 다른 하나는 책값 합계를 이름으로 남긴다.
- 자료:

```swift
let totalCost = participantCount * bookPrice + deliveryFee
```

```swift
let bookSubtotal = participantCount * bookPrice
let totalCost = bookSubtotal + deliveryFee
```

- 첫 질문: 참여자 수가 잘못됐을 때 어느 코드가 처음 달라지는 단계를 더 빨리 찾게 하는가?

[개념 대조]

- 비교 기준: 결과만 압축한 한 줄 | 계산 책임을 이름 붙인 여러 단계
- 항목: 한 줄 식은 짧지만 관계 경계가 숨는다 | `bookSubtotal`은 책 비용 계산의 결과와 다음 입력 역할을 함께 가진다 | 중간값 이름은 계산 이유를 설명하고 관찰 지점을 제공한다
- 관찰 질문: 줄 수가 늘어나는 비용보다 의미와 검증 지점이 생기는 이점이 큰가?

[개념 정의]

- 개념: 중간값
- 한 문장 정의: 중간값은 큰 계산의 한 단계에서 만들어져 다음 계산의 입력으로 다시 쓰이는 이름 붙은 결과값이다.
- 적용 범위: `bookSubtotal`은 곱셈의 결과이자 전체 비용 덧셈의 입력이다.
- 지식 링크: [[지식 체계/03 표현식과 연산/중간값|중간값]]

## 적용

[지식 연결]

- 지식 링크: [[지식 체계/03 표현식과 연산/중간값|중간값]], [[지식 체계/02 값과 타입/식별자와 이름 짓기|식별자와 이름 짓기]], [[지식 체계/01 문제 해결과 컴퓨팅 사고/입력 규칙 출력 구조|입력·규칙·출력 구조]]
- 이 페이지에서의 쓰임: 하나의 의미 관계가 끝나고 그 결과가 다음 관계의 입력이 되는 지점을 중간값 경계로 잡는다.
- 표시 시점: 두 코드 대조 뒤 펼친다.

[코드 조립]

- 시작 코드:

```swift
let ____ = participantCount * bookPrice
let ____ = ____ + deliveryFee
```

- 조각: `bookSubtotal` | `totalCost` | `participantCount` | `bookPrice` | `deliveryFee`
- 고정 부분: 첫 줄은 책값 합계, 둘째 줄은 전체 준비 비용이라는 책임을 유지한다.
- 완료 조건: 두 선언을 완성하고 각 중간값에 `입력 → 관계 → 결과 → 다음 사용` 설명을 붙인다.

[자유 작성]

- 과제: `bookSubtotal`이 필요한 이유를 “짧아서”가 아닌 책임과 오류 추적 관점으로 설명한다.
- 입력 형식: `중간값 이름 → 맡은 계산 → 다음 사용 → 값이 다르면 먼저 확인할 입력`
- 필수 근거: `participantCount` 또는 `bookPrice` 변경 영향을 포함한다.
- 제출 뒤 예시: `bookSubtotal → 책 수량과 가격으로 책 비용을 만든다 → totalCost의 입력 → 다르면 수량과 가격부터 확인한다.`

## 성찰

[학습 마무리]

- 첫 예상: 큰 식을 처음 나눈 경계와 이름
- 최종 설명: 수정한 중간값 경계와 단계 흐름
- 확신 변화: 다시 고른 확신과 영향을 준 근거를 적는다.
- 바뀐 기준: 줄 길이가 아니라 의미 관계가 끝나는 지점으로 계산을 나누게 되었는지 적는다.
- 다음에 쓸 장소: 여러 연산이 한 식에 있을 때 실제 평가 순서를 확인한다.
- 확인 질문: 중간값이 다음 계산의 입력이 되는 흐름을 설명할 수 있는가?
- 필요한 증거: 단계별 입력, 표현식, 중간값 이름, 다음 사용, 변경 영향
- 다시 시도 조건: 식을 기계적으로 반으로 나눴다면 한 관계의 결과가 다음 관계의 입력이 되는 지점을 다시 찾는다.
