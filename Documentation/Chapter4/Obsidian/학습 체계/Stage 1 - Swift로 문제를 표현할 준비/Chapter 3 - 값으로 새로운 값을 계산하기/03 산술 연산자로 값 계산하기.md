# 산술 연산자로 값 계산하기

> 페이지 목표: 자연어가 말하는 값의 관계를 근거로 `+`, `-`, `*`, `/` 연산자를 선택한다.

## 방향잡기

[학습 나침반]

- 이전 연결: 2페이지에서 표현식이 입력을 평가해 결과 하나를 만든다고 보았다.
- 핵심 질문: 문제 문장의 어떤 관계가 어떤 산술 연산을 요구할까?
- 첫 예상: `한 권 가격을 네 명만큼 반복`, `배송비를 합침`, `예산에서 비용을 제외`, `전체를 인원수로 나눔`을 기호와 연결한다.
- 초기 확신: 낮음 | 중간 | 높음과 이유를 적는다.
- 완료 증거: 새 문장의 관계를 연산자로 옮기고 입력 순서와 선택 이유를 설명한다.

## 탐색

[상황 제시]

- 제목: 기호보다 먼저 있는 관계
- 상황: 같은 두 숫자라도 문제에서 합침, 차이, 반복, 균등 분배 중 무엇을 묻는지에 따라 식이 달라진다.
- 자료: 합친다 | 남은 것을 구한다 | 같은 양을 여러 번 센다 | 같은 크기로 나눈다
- 첫 질문: 숫자 모양만 보고 연산자를 고를 수 있는가?

[카드 분류]

- 카드: 책값에 배송비를 합친다 | 예산에서 전체 비용을 뺀다 | 한 권 가격을 참여자 수만큼 센다 | 전체 금액을 사람 수로 나눈다
- 분류 영역: `+` | `-` | `*` | `/`
- 조작: 문장의 동사와 결과 의미를 근거로 먼저 분류한다.
- 완료 조건: 네 관계를 모두 연결하고, `-`와 `/`에서는 왼쪽·오른쪽 입력 순서도 표시한다.
- 피드백 기준: 단어 하나가 아니라 구하려는 결과와 입력의 역할을 다시 묻는다.

[판단 기준]

- 기준 질문: 양을 합치는가? 기준에서 일부를 제외하는가? 같은 양을 여러 번 묶는가? 전체를 같은 크기로 나누는가?
- 적용 순서: 구할 결과 확인 → 입력 역할 확인 → 관계 동사 확인 → 입력 순서 확인 → 결과 단위 예상
- 주의점: 자연어의 `더`가 언제나 `+`를 뜻하지 않고, `배`나 `남은`처럼 결과 의미를 함께 봐야 한다.

## 적용

[지식 연결]

- 지식 링크: [[지식 체계/03 표현식과 연산/산술 연산|산술 연산]], [[지식 체계/03 표현식과 연산/표현식|표현식]], [[지식 체계/02 값과 타입/타입 선택|타입 선택]]
- 이 페이지에서의 쓰임: 연산 기호를 암기표가 아니라 입력값 사이의 관계를 표현하는 도구로 사용한다.
- 표시 시점: 첫 분류 뒤 근거가 필요할 때 펼친다.

[코드 조립]

- 시작 코드: `let result = ____`
- 조각: `bookSubtotal` | `deliveryFee` | `budget` | `participantCount` | `+` | `-` | `*` | `/`
- 고정 부분: 문제마다 `result`를 `totalCost`, `remainingBudget`, `bookSubtotal` 중 의미 있는 이름으로 바꾼다.
- 완료 조건: 세 문제의 식을 만들고 각 식에 자연어 관계와 예상 단위를 적는다.

[선택 후 설명]

- 질문: `예산 100_000원에서 전체 비용 75_000원을 제외한 남은 예산`을 표현하는 식은 무엇인가?
- 선택지: `100_000 - 75_000` | `75_000 - 100_000` | `100_000 + 75_000`
- 이유 입력: 어떤 값이 기준이고 무엇을 제외하는지 적는다.
- 판단 피드백: 결과 부호만 보지 않고 기준량과 제외량의 역할로 돌아간다.

## 성찰

[학습 마무리]

- 첫 예상: 네 자연어 관계와 연산자의 최초 연결
- 최종 설명: 연산자별 관계와 입력 순서를 자신의 말로 설명한다.
- 확신 변화: 다시 고른 확신과 영향을 준 근거를 적는다.
- 바뀐 기준: 동사나 기호 모양보다 결과 의미와 입력 역할을 더 보게 되었는지 적는다.
- 다음에 쓸 장소: 여러 연산이 있는 큰 계산을 의미 있는 중간값으로 나눈다.
- 확인 질문: 처음 보는 자연어 관계를 산술 표현식으로 옮길 수 있는가?
- 필요한 증거: 표현식, 입력 역할, 연산 선택 이유, 예상 결과 단위
- 다시 시도 조건: 기호만 골랐다면 각 입력이 전체·부분·반복량·묶음 수 중 무엇인지 다시 이름 붙인다.
