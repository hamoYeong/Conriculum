# 의미가 드러나는 이름 붙이기

> 페이지 목표: 값의 대상과 역할이 코드에서 드러나도록 Swift 식별자를 만들고 선택 근거를 설명한다.

## 방향잡기

[학습 나침반]

- 이전 연결: 3페이지에서 정보의 의미와 할 일으로 타입을 골랐다. 이제 같은 타입의 값도 코드에서 역할로 구분되게 한다.
- 핵심 질문: 값과 타입을 가려도 이 이름만으로 무엇을 가리키고 어떤 역할인지 예상할 수 있는가?
- 첫 예상: `value`, `number`, `flag`, `name`에 각각 `20_000`, `2`, `true`, `"푸른고래"`가 있을 때 정확한 역할을 알 수 있는지 적는다.
- 초기 확신: 낮음 | 중간 | 높음과 그 이유를 적는다.
- 완료 증거: 모호한 이름 세 개를 대상·역할·필요한 구분으로 개선하고, Bool 이름을 `true`일 때 자연스럽게 읽는다.

## 탐색

[상황 제시]

- 제목: 값만 남은 주문 코드
- 상황: `20_000`, `2`, `true`, `"푸른고래"`가 주문 화면에 필요하지만 어떤 값이 금액·수량·회원 여부·닉네임인지 이름에서 보이지 않는다.
- 자료:

```swift
let value = 20_000
let number = 2
let flag = true
let name = "푸른고래"
```

- 첫 질문: 코드 뒤쪽의 값을 가린다면 각 이름이 무엇을 가리키는지 알 수 있을까?

[코드 조립]

- 시작 코드: 위 네 선언의 오른쪽 값을 유지하고 식별자만 빈칸으로 보인다.
- 조각: `orderAmount` | `quantity` | `isMember` | `customerNickname` | `data` | `status`
- 고정 부분: `let`, 등호, 오른쪽 값
- 완료 조건: 네 값에 이름을 붙이고 남은 모호한 이름을 제외한 이유를 적는다.

[개념 대조]

- 비교 기준: 이름만으로 대상·역할·Bool의 참 의미가 드러나는가?
- 항목: `value → orderAmount` | `number → quantity` | `flag → isMember` | `name → customerNickname`
- 관찰 질문: 같은 `Int`인 `orderAmount`와 `quantity`를 타입이 아니라 무엇으로 구분하는가?

[개념 정의]

- 개념: 식별자와 이름 짓기
- 한 문장 정의: 식별자는 코드의 대상을 가리키는 이름이며, 좋은 이름은 값의 대상과 현재 문제에서의 역할을 드러낸다.
- 적용 범위: 상수에 lowerCamelCase 이름을 쓰고, Bool은 참일 때 자연스러운 질문과 답으로 읽히게 한다.
- 지식 링크: [[지식 체계/02 값과 타입/식별자와 이름 짓기|식별자와 이름 짓기]]

[판단 기준]

- 기준 질문: 무엇을 가리키는가? 어떤 역할을 하는가? 같은 타입의 다른 값과 구분되는가? Bool이 `true`일 때 자연스럽게 읽히는가?
- 적용 순서: 대상 → 역할 → 필요한 구분 → Swift 표기 관례
- 주의점: `value`, `data`, `number`, `status`처럼 타입이나 넓은 범주만 반복하는 이름을 피한다.

## 적용

[지식 연결]

- 지식 링크: [[지식 체계/02 값과 타입/식별자와 이름 짓기|식별자와 이름 짓기]]
- 이 페이지에서의 쓰임: 타입만으로 구분하지 못하는 값의 대상과 역할을 코드에 남긴다.
- 표시 시점: 첫 이름 개선을 마친 뒤에 펼친다.

[코드 조립]

- 시작 코드:

```swift
let price = 20_000
let amount = 2_000
let status = true
```

- 조각: `orderAmount` | `memberDiscountAmount` | `isMember` | `isPaid` | 사용자 식별자 입력
- 고정 부분: `let`, 등호, 오른쪽 값
- 완료 조건: 상황을 `회원 할인을 표시하는 주문 확인`으로 정하고 세 이름을 개선한 뒤 각 이름이 드러낸 대상과 역할을 적는다.

[선택 후 설명]

- 질문: 회원 여부를 나타내는 Bool 이름으로 `member`, `status`, `isMember` 중 무엇이 가장 자연스러운가?
- 선택지: `member` | `status` | `isMember`
- 이유 입력: `이름 = true`를 자연어 문장으로 읽어 설명한다.
- 판단 피드백: Bool 이름을 참일 때의 질문과 답으로 되돌려 준다.

## 성찰

[학습 마무리]

- 첫 예상: 나침반의 모호한 이름 판단
- 최종 설명: 값과 타입을 가린 채 개선한 이름의 대상과 역할을 설명한다.
- 확신 변화: 낮음 | 중간 | 높음을 다시 고르고 이름이 제공한 증거를 적는다.
- 바뀐 기준: 짧음·영어다움보다 대상·역할·구분을 더 중요하게 보게 되었는지 적는다.
- 다음에 쓸 장소: 이름에 값을 담을 때 같은 이름이 새 값을 가리킬 수 있는지 변경 약속을 정한다.

- 확인 질문: 값만 보고 이름을 붙이는 대신 문제 속 역할을 이름에 담을 수 있는가?
- 필요한 증거: 개선 전 이름 세 개, 개선 후 이름, 드러난 대상·역할, Bool 이름을 문장으로 읽은 결과
- 다시 시도 조건: 이름이 타입이나 넓은 범주만 반복한다면 같은 타입의 다른 값과 구분되는지 확인한다.
