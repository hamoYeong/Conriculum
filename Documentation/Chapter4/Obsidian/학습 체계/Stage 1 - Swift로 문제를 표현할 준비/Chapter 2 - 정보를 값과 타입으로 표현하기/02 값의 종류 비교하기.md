# 값의 종류 비교하기

> 페이지 목표: 값의 표기와 허용되는 일을 비교해 `String`, `Int`, `Double`, `Bool`의 차이를 설명한다.

## 방향잡기

[학습 나침반]

- 이전 연결: 1페이지에서 `"푸른고래"`, `20_000`, `true`를 구체적인 값으로 찾았다. 이제 각 값이 무엇을 할 수 있는지 비교한다.
- 핵심 질문: 이 값으로 어떤 일을 해야 하며, 그 일을 허용하는 타입은 무엇인가?
- 첫 예상: `"푸른고래"`, `2`, `4.5`, `true`를 보고 각각 할 수 있는 일 하나와 바로 할 수 없는 일 하나를 적는다.
- 초기 확신: 낮음 | 중간 | 높음과 그 이유를 적는다.
- 완료 증거: 네 기본 타입을 리터럴 모양만이 아니라 허용된 일과 경계 사례로 구분한다.

## 탐색

[상황 제시]

- 제목: 보이는 모양보다 다음에 할 일
- 상황: 앱은 닉네임을 표시하고, 수량을 세고, 별점 평균의 소수 부분을 보존하고, 회원 여부로 판단해야 한다.
- 자료: `"푸른고래"` | `2` | `4.5` | `true`
- 첫 질문: 네 값을 서로 바꾸어 놓아도 같은 일을 수행할 수 있을까?

[카드 분류]

- 카드: 글자 그대로 보존·표시 | 온전한 개수 세기 | 소수 부분 보존 | 예·아니오 판단 | 앞자리 0 보존 | 금액 더하기
- 분류 영역: `"푸른고래"` | `2` | `4.5` | `true`
- 조작: 개념 이름을 보기 전에 각 값으로 할 수 있는 일을 연결한다. 앞자리 0과 금액은 새 값 예시를 작성해 연결한다.
- 완료 조건: 여섯 일을 연결하고, 두 값을 서로 바꾸었을 때 깨지는 일 하나를 설명한다.
- 피드백 기준: 표기 단서를 인정하되 `앱이 이 값으로 무엇을 할까?`를 다시 묻는다.

[개념 정의]

- 개념: 타입과 네 기본 타입
- 한 문장 정의: 타입은 값이 어떤 정보이며 어떤 사용이 허용되는지를 정하는 약속이다.
- 적용 범위: `String`은 글자, `Int`는 정수, `Double`은 소수 부분이 있는 수, `Bool`은 참·거짓 두 상태를 다룬다.
- 지식 링크: [[지식 체계/02 값과 타입/타입|타입]], [[지식 체계/02 값과 타입/String|String]], [[지식 체계/02 값과 타입/Int|Int]], [[지식 체계/02 값과 타입/Double|Double]], [[지식 체계/02 값과 타입/Bool|Bool]]

[개념 대조]

- 비교 기준: 표기 | 주요 의미 | 허용할 일 | 경계 사례
- 항목:

| 값 | 타입 | 주요 의미와 일 | 경계 사례 |
| --- | --- | --- | --- |
| `"푸른고래"` | `String` | 글자 순서를 보존하고 표시한다. | `"01234"`는 숫자 모양이어도 글자를 보존한다. |
| `2` | `Int` | 소수 부분 없이 세고 정수 계산을 한다. | 평균 `2.5`는 보존하지 못한다. |
| `4.5` | `Double` | 소수 부분을 포함한 수치를 다룬다. | 정확한 소수 표현 전체를 보장하는 타입으로 오해하지 않는다. |
| `true` | `Bool` | 참·거짓 두 상태를 판단한다. | 대기·확정·취소 세 상태는 충분히 담지 못한다. |

- 관찰 질문: `20_000`과 `"20,000원"`은 같은 대상을 떠올리게 하지만 왜 다른 일을 하게 되는가?

## 적용

[지식 연결]

- 지식 링크: [[지식 체계/02 값과 타입/타입|타입]], [[지식 체계/02 값과 타입/String|String]], [[지식 체계/02 값과 타입/Int|Int]], [[지식 체계/02 값과 타입/Double|Double]], [[지식 체계/02 값과 타입/Bool|Bool]]
- 이 페이지에서의 쓰임: 리터럴을 타입에 연결하고, 타입을 할 수 있는 일과 할 수 없는 일로 구분한다.
- 표시 시점: 첫 연결 시도 뒤 필요한 타입만 보여 준다.

[대응 연결]

- 왼쪽 항목: 책 제목 표시 | 재고 수량 합계 | 적립률 보존 | 배송 완료 판단 | 우편번호 `01234` 그대로 보존 | 결제 금액 더하기
- 오른쪽 항목: `String` | `Int` | `Double` | `Bool`
- 연결 규칙: 하나의 일에 타입을 연결하고, 그 타입의 예시 값과 바로 못 하는 일을 함께 적는다.
- 완료 조건: 여섯 일을 모두 연결하고 우편번호와 결제 금액이 다른 타입인 이유를 설명한다.

[판단 기준]

- 기준 질문: 글자 내용을 보존하는가? 소수 없이 세는가? 소수 부분이 필요한가? 참·거짓 두 상태로 충분한가?
- 적용 순서: 할 일 예상 → 표기 단서 확인 → 타입 연결 → 경계 사례 확인
- 주의점: 현실의 많은 상태는 네 기본 타입만으로 충분히 표현되지 않는다.

## 성찰

[학습 마무리]

- 첫 예상: 나침반에서 적은 가능한 일과 불가능한 일
- 최종 설명: 네 타입을 하나의 예시·할 일·경계로 다시 설명한다.
- 확신 변화: 낮음 | 중간 | 높음을 다시 고르고 설명 근거를 적는다.
- 바뀐 기준: 표기 암기에서 허용되는 일과 경계 판단으로 어떻게 바뀌었는지 적는다.
- 다음에 쓸 장소: 표기만 보고 타입을 알아맞히는 대신 새 정보의 의미와 사용으로 타입을 선택한다.

- 확인 질문: 네 기본 타입을 이름보다 할 수 있는 일과 경계로 구분할 수 있는가?
- 필요한 증거: 타입 네 개의 서로 다른 예시, 사용 목적, 경계 사례 각 하나
- 다시 시도 조건: 리터럴 모양만 근거로 썼다면 앱이 그 값으로 할 일과 바로 할 수 없는 일을 추가한다.

## 선택 학습과 개인 지식화

[확장 과제]

- 표시 조건: `지루함(쉬움) - 더 깊게 가기`를 선택했을 때
- 추가 자료: 우편번호 `"01234"`, 재고 코드 `"0007"`, 재고 수량 `7`
- 추가 활동: 숫자 모양이어도 글자로 보존할 값과 수량으로 계산할 값을 사용 목적으로 나눈다.
- 연결 지식: [[지식 체계/02 값과 타입/타입 선택|타입 선택]]

[개인 지식 반영]

- 근거 활동: `[대응 연결]`의 타입·할 일·경계 연결과 `[학습 마무리]`의 설명
- 연결 지식: 학습자가 고른 `String`, `Int`, `Double`, `Bool` 중 하나
- 후보 유형: 나의 타입 설명과 경계 예시
- 편집 가능한 초안: 선택한 타입에 맞춰 `Int는 온전한 개수를 세거나 정수 계산에 쓰며, 소수 부분은 보존하지 못한다.`처럼 제안한다.
- 확인 질문: 페이지를 완료한 뒤 이 설명을 나의 언어로 남길까?
- 저장 항목: 대상 concept ID, 나의 설명, 나의 예시, 경계 예시, 근거 활동 ID, 수정 시각
- 취소 결과: 연결과 설명 응답은 유지하고 개인 지식은 변경하지 않는다.
