# 타입 명시와 타입 추론 비교하기

> 페이지 목표: 타입 표기가 없어도 Swift가 알아낸 타입을 읽고, 의도를 드러낼 필요에 따라 추론과 명시를 선택한다.

## 방향잡기

[학습 나침반]

- 이전 연결: 선언의 값·타입·이름·변경 약속을 정했다. 이제 타입을 코드에 얼마나 직접 드러낼지 선택한다.
- 핵심 질문: 오른쪽 표현만으로 Swift가 타입을 알 수 있는가, 그리고 독자에게 그 타입 약속을 직접 보여 줘야 하는가?
- 첫 예상: `let orderAmount = 20_000`과 `let orderAmount: Int = 20_000`의 실제 타입과 표기 차이를 적는다.
- 초기 확신: 낮음 | 중간 | 높음과 이유를 적는다.
- 완료 증거: 추론 선언과 명시 선언의 실제 타입을 말하고, 타입 표기가 의도 전달에 더한 정보를 근거로 표기 방식을 선택한다.

## 탐색

[상황 제시]

- 제목: 같은 값을 선언하는 두 방식
- 상황: 두 선언은 모두 주문 금액 20,000을 `Int`로 다룬다.
- 자료:

```swift
let orderAmount = 20_000
let orderAmount: Int = 20_000
```

- 첫 질문: 첫 줄에 `Int`가 보이지 않으면 타입이 없는 것일까?

[선택 후 설명]

- 질문: 두 선언의 실제 타입과 타입 정보가 오는 곳을 설명한다.
- 선택지: 첫 줄만 타입이 있다 | 둘 다 `Int`이다 | 둘째 줄만 `Int`이다
- 이유 입력: 리터럴 `20_000`과 표기 `: Int`가 각각 제공하는 정보를 나눈다.
- 판단 피드백: 타입 표기의 유무와 실제 타입의 유무를 분리해 되묻는다.

[개념 대조]

- 비교 기준: 타입을 누가 어떤 단서로 알아내며 선언에 얼마나 직접 보이는가?
- 항목: 타입 추론 → 리터럴과 문맥에서 Swift가 타입을 알아낸다. | 타입 명시 → 개발자가 `: Int`처럼 타입을 직접 적어 약속을 드러낸다.
- 관찰 질문: 두 선언이 같은 타입인데도 표기를 다르게 고를 이유는 무엇인가?

[개념 정의]

- 개념: 타입 추론과 타입 명시
- 한 문장 정의: 추론은 표현에서 Swift가 타입을 알아내는 기능이고, 명시는 개발자가 의도한 타입을 코드에 직접 적는 표기다.
- 적용 범위: 추론 결과가 의도와 같은지 먼저 확인하고, 특정 타입 약속을 독자에게 드러내는 것이 유용할 때 명시를 검토한다.
- 지식 링크: [[지식 체계/02 값과 타입/타입 추론과 타입 명시|타입 추론과 타입 명시]]

[판단 기준]

- 기준 질문: Swift가 추론할 타입은 무엇인가? 그 결과가 의도와 같은가? 타입 표기가 독자에게 새 정보나 약속을 주는가?
- 적용 순서: 추론 결과 예상 → 의도와 비교 → 독자에게 필요한 약속 → 표기 선택
- 주의점: 타입을 명시해도 이름이 모호하면 값의 역할은 분명해지지 않는다.

## 적용

[지식 연결]

- 지식 링크: [[지식 체계/02 값과 타입/타입 추론과 타입 명시|타입 추론과 타입 명시]], [[지식 체계/02 값과 타입/리터럴|리터럴]]
- 이 페이지에서의 쓰임: 타입 정보가 오는 곳과 표기가 더하는 의도를 나눈다.
- 표시 시점: 첫 추론 예상 뒤에 펼친다.

[빈칸 완성]

- 시작 내용:

```swift
let orderAmount: ___ = 20_000
let isMember: ___ = true
let customerNickname: ___ = "푸른고래"
let discountRate = 0.1
```

- 빈칸: 세 선언의 타입과 네 번째 선언의 추론 타입
- 선택 항목: `String` | `Int` | `Double` | `Bool`
- 완료 조건: 네 타입을 완성하고, 타입 표기를 생략할 선언 하나와 직접 남길 선언 하나의 이유를 적는다.

[선택 후 설명]

- 질문: `let customerNickname = "푸른고래"`에 `: String`을 반드시 적어야 하는가?
- 선택지: 반드시 적어야 한다 | 생략해도 Swift가 추론한다 | 타입이 생기지 않는다
- 이유 입력: 리터럴이 제공하는 타입 단서와 표기를 추가할 때의 의도를 구분한다.
- 판단 피드백: `짧아서`와 `길어서`보다 실제 타입과 독자에게 전할 약속을 묻는다.

## 성찰

[학습 마무리]

- 첫 예상: 나침반의 두 선언 비교
- 최종 설명: 타입 표기가 없어도 실제 타입이 있는 이유와 명시가 유용한 사례
- 확신 변화: 낮음 | 중간 | 높음을 다시 고르고 추론 결과를 설명할 수 있는지로 이유를 적는다.
- 바뀐 기준: 타입 표기 유무에서 실제 타입·추론 단서·의도 전달로 어떻게 바뀌었는지 적는다.
- 다음에 쓸 장소: 여러 선언을 사례에서의 역할로 묶어 읽는다.

- 확인 질문: 타입 표기가 없어도 타입이 있는 이유와 타입을 직접 적을 이유를 구분할 수 있는가?
- 필요한 증거: 추론 선언 하나, 명시 선언 하나, 각 실제 타입, 선택 이유
- 다시 시도 조건: `짧아서`·`길어서`만 근거라면 추론 결과와 독자에게 보여 줄 약속을 다시 적는다.
