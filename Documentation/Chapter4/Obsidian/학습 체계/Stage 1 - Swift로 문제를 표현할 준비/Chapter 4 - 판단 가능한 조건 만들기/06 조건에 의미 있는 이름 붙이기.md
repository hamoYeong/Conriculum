# 조건에 의미 있는 이름 붙이기

## 목표

작은 판단과 전체 판단에 의미 있는 Bool 이름을 붙이고 저장된 결과와 규칙을 구분한다.

공통 구조와 개인 지식 반영 규칙은 [[학습 체계/00 학습 체계 지도|학습 체계 지도]]를 따른다.

## 방향잡기

[학습 나침반]

### 이번 판단의 나침반

<!-- section: section-ch04-page06-compass; activity: activity-ch04-page06-compass -->

- 이전 연결: 작은 질문들을 조합했다. 이제 그 질문의 책임이 코드에서 드러나도록 이름을 붙인다.
- 핵심 질문: 조건이 참일 때 어떤 사실인지 이름만으로 읽을 수 있을까?
- 첫 예상: let check = totalCost >= 50_000과 let meetsMinimum = totalCost >= 50_000 중 판단을 더 잘 설명하는 이름을 고르고 이유를 적는다.
- 초기 확신: 낮음 | 중간 | 높음과 지금 그렇게 예상한 이유를 남긴다.
- 완료 증거:
  - 이름과 판단 의미
  - 작은 판단과 전체 판단의 흐름
  - 저장값과 재평가의 차이

## 탐색

[상황 제시]

<!-- section: section-ch04-page06-situation -->

- 제목: 조건에 의미 있는 이름 붙이기
- 상황: 배송 혜택 대상 여부를 isMember && (totalCost >= 50_000)으로 표현했다. 금액 조건을 따로 읽고 다른 곳에서도 사용하려 한다.
- 자료:
  - 항목:
    - 자료 이름: 입력
    - 내용:

      ```swift
      let totalCost = 75_000
      let isMember = true
      ```
  - 항목:
    - 자료 이름: 다듬을 코드
    - 내용:

      ```swift
      let check = totalCost >= 50_000
      let flag = check && isMember
      ```
- 첫 질문: 조건이 참일 때 어떤 사실인지 이름만으로 읽을 수 있을까?

## 기준 발견

[판단 기준]

<!-- section: section-ch04-page06-criteria -->

- 기준 질문:
  - 참일 때 성립하는 사실이 이름에 있는가?
  - 한 이름이 하나의 작은 책임을 맡는가?
  - 저장한 값은 언제 계산되었는가?
- 적용 순서:
  - 첫 예상을 확인한다.
  - 자료를 기준 질문으로 살펴본다.
  - 새 사례에 같은 기준을 적용하고 이유를 설명한다.
- 주의점: let에 저장된 Bool은 선언 시 평가한 값이다. 원래 입력이 바뀌면 조건식도 다시 평가해야 하며 이름 자체가 자동 갱신 규칙은 아니다.

## 적용

[자유 작성]

### 하나의 판단을 끝까지 설명하기

<!-- section: section-ch04-page06-work; activity: activity-ch04-page06-work -->

- 질문: check와 flag를 의미 있는 이름으로 바꾸고 금액 판단 → 회원과 조합 → 전체 판단 흐름을 설명한다. 새 주문 40,000원에 같은 코드를 다시 적용했을 때의 결과도 적는다.
- 입력 형식: 이름 붙인 선언 두 줄 → 역할 → 새 입력의 결과
- 필수 근거:
  - 작은 판단 이름
  - 전체 판단 이름
  - 평가 시점
  - 새 입력 결과
- 제출 뒤 예시:

  ```swift
  let meetsMinimum = totalCost >= 50_000
  let isEligible = meetsMinimum && isMember
  75,000원·회원이면 두 값 모두 true다. 새 주문 40,000원으로 다시 평가하면 둘 다 false다. 이전에 저장한 Bool이 자동으로 바뀌는 것은 아니다.
  ```
