# Chapter 4 학습 경험 설계

[[학습 체계/00 학습 체계 지도#새 Chapter 생성 계약|새 Chapter 생성 계약]]을 Chapter 4에 적용한 설계다.

## 1. 화면 전체에서 만들 경험

학습자는 조건식을 기호로 번역하는 데서 나아가 **같은 입력에서 같은 답이 나오는 질문을 만들고 반례로 그 뜻을 확인**한다. 전체 화면은 현재 판단 하나를 유지하며, 정답 결과보다 입력·기준·경계·조합의 근거를 남기게 한다.

## 2. 화면 영역의 역할

- 최상단: 이전 계산 결과와 이번 질문, 설명 전 예상과 확신, 완료 증거를 보여 준다.
- 메인 스크롤: 하나의 문제에서 기준을 발견하고 핵심 응답을 만든다. 코드와 기대값·이유를 한 작업 표면에서 다룬다.
- 지식 문맥: 핵심 질문, 핵심 개념 하나와 보조 최대 두 개를 유지한다. 연산자 설명 전체나 페이지를 반복하지 않는다.
- Inspector: 기본 설명과 확인해 저장한 나의 표현을 읽고 비교한다. 편집과 후보 저장은 명시적으로 선택할 때만 연다.

## 3. 페이지에서 블록으로 내려가는 흐름

Overview는 Chapter 3의 totalCost를 받으며 전체 경로와 완료 증거를 예고한다. 1~3은 질문을 값과 식으로 바꾸고, 4~6은 경계·조합·이름을 다듬는다. 7은 잘못된 조건을 고치고, 8은 체험 교실이라는 새 상황에 전이한다. 9는 같은 코드의 떨어진 요소를 책임과 데이터 흐름으로 통합해 다음 Chapter에 넘긴다.

각 lesson은 나침반의 첫 예상 → 상황 → 판단 기준 → 하나의 핵심 활동 → 지식 연결 → 마무리 순서다. 8은 독립 전이를 위해 작업 전 판단 기준 블록을 생략하고, 모델 답은 제출 뒤에만 보여 준다. 9는 선언 순서가 유효한 실행 가능 코드 안에 다른 역할의 요소를 끼워 넣어 비연속 묶기를 연습한다.

## 4. 블록 안의 순서와 피드백

- 나침반은 답을 미리 설명하지 않고 첫 예상과 근거를 받는다.
- 선택·자유 작성은 결과뿐 아니라 입력·기준·경계·조합 이유를 요구한다.
- 틀렸을 때 정답을 복사하기보다 경계와 일부 조건만 참인 사례로 돌아간다.
- 마무리는 첫 예상과 최종 설명, 확신 변화, 바뀐 기준, 다음 사용과 재시도 근거를 한 흐름으로 받는다.
- 4·5·8의 추가 문제는 마무리 뒤 접힌 확장 영역에 둔다.
- 개인 지식 반영은 핵심 수행 뒤 확인을 거치는 선택 흐름이다. 활동 응답의 자동 저장과 개념 revision 저장을 구분한다.

## 5. Sidebar 내부 구성

질문 한 문장 → 핵심 기준 하나 → 보조 개념 최대 두 개 → 확인된 변화 → 인접 지식 순서다. 후보를 확인된 변화로 표시하지 않는다. 개인 지식 저장이나 Inspector 사용은 완료 조건이 아니다.

## 6. 데이터와 컴포넌트 계약

Overview와 9개 lesson의 학습·section·activity ID를 고정한다. Markdown 내용을 Chapter JSON과 지식 catalog 및 manifest로 승격한다. 기존 공용 학습 나침반·상황·판단 기준·선택 후 설명·자유 작성·의미 단위 조각 읽기·학습 마무리·개인 지식 반영 SwiftUI 컴포넌트를 조합한다.

Chapter 3의 마지막 페이지는 Chapter 4 Overview를 다음 목적지로 가리킨다. 새 진입은 Overview에서 시작하고, 이미 진행한 Chapter 4는 유효한 저장 위치에서 이어간다. 마지막 lesson의 다음 학습은 Chapter 5이며 아직 번들에 없는 경우 기존 준비 중 안내를 유지한다.
