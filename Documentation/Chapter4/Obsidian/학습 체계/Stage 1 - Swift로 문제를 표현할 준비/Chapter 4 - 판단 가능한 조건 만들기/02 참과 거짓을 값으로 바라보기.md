# 참과 거짓을 값으로 바라보기

## 목표

판단의 답을 Bool 값으로 표현하고 질문·결과값·텍스트를 구분한다.

공통 구조와 개인 지식 반영 규칙은 [[학습 체계/00 학습 체계 지도|학습 체계 지도]]를 따른다.

## 방향잡기

[학습 나침반]

### 이번 판단의 나침반

<!-- section: section-ch04-page02-compass; activity: activity-ch04-page02-compass -->

- 이전 연결: 앞에서 “전체 금액이 50,000원 이상인가?”라는 질문을 만들었다. 이제 그 답도 하나의 값으로 읽는다.
- 핵심 질문: 참이라는 답과 그 답을 만드는 질문은 어떻게 다를까?
- 첫 예상: true, "true", totalCost >= 50_000 중 각각 값의 타입과 역할을 먼저 예상한다.
- 초기 확신: 낮음 | 중간 | 높음과 지금 그렇게 예상한 이유를 남긴다.
- 완료 증거:
  - Bool 결과와 타입
  - String과의 차이
  - 입력이 달라진 질문의 답

## 탐색

[상황 제시]

<!-- section: section-ch04-page02-situation -->

- 제목: 참과 거짓을 값으로 바라보기
- 상황: 전체 금액 75,000원은 기준을 충족한다. 이 사실을 화면 문구와 계산 가능한 판단값으로 각각 기록해 본다.
- 자료:
  - 항목:
    - 자료 이름: 비교할 코드
    - 내용:

      ```swift
      let totalCost = 75_000
      let meetsMinimum = totalCost >= 50_000
      let message = "true"
      ```
- 첫 질문: 참이라는 답과 그 답을 만드는 질문은 어떻게 다를까?

## 기준 발견

[판단 기준]

<!-- section: section-ch04-page02-criteria -->

- 기준 질문:
  - 질문을 평가하기 전 식인가, 평가한 결과인가?
  - 따옴표가 있는 텍스트인가?
  - false는 확인 결과 거짓인가, 아직 모르는가?
- 적용 순서:
  - 첫 예상을 확인한다.
  - 자료를 기준 질문으로 살펴본다.
  - 새 사례에 같은 기준을 적용하고 이유를 설명한다.
- 주의점: Swift의 조건에는 Bool을 사용한다. "true"나 숫자 1을 Bool 대신 쓰지 않는다. 미확인을 false로 숨기지 않는다.

## 적용

[선택 후 설명]

### 하나의 판단을 끝까지 설명하기

<!-- section: section-ch04-page02-work; activity: activity-ch04-page02-work -->

- 기준 질문:
  - 항목:
    - 항목 ID: judgment
    - 질문: meetsMinimum과 message를 올바르게 구분한 것은?
    - 선택지:
      - 항목:
        - 항목 ID: option-1
        - 내용: 둘 다 Bool이며 값은 true다.
      - 항목:
        - 항목 ID: option-2
        - 내용: meetsMinimum은 Bool의 true, message는 String의 "true"다.
      - 항목:
        - 항목 ID: option-3
        - 내용: meetsMinimum은 Int의 75_000이다.
- 이유 입력: totalCost가 40,000원인 코드로 다시 평가할 때 두 값이 어떻게 되는지 설명한다.
- 판단 피드백:
  - 따옴표와 비교 연산 결과의 타입을 확인한다.
  - 비교에 사용한 숫자와 비교 결과를 구분한다.
