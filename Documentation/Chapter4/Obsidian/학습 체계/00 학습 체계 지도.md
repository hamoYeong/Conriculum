# 학습 체계 지도

학습 체계는 학습자가 사고 행동을 하나씩 연습하며 따라가는 **선형적 경로**다. 반면 [[지식 체계/00 지식 체계 지도|지식 체계]]는 개념을 비선형적으로 저장해 여러 학습 페이지에서 재사용한다. 학습 페이지는 필요한 순간에 지식 노트를 연결해 사용하고, 학습자는 기본 개념을 자신의 언어로 다시 표현하며 자신에게 의미 있는 관계를 만든다.

## 선형 학습과 개인 지식의 순환

```text
선형 학습 페이지 수행
→ 현재 활동에 필요한 기본 지식 사용
→ 활동 응답과 판단 설명을 학습 증거로 기록
→ 개인 지식으로 삼을 표현과 연결을 학습자가 확인
→ 비선형 개인 지식 체계에 반영
→ 이후 학습에서 기본 지식과 개인 지식을 함께 다시 사용
```

- 학습 페이지는 지식 노트를 소유하거나 복제하지 않고 지식에 연결된다.
- 학습 응답과 개인 지식은 구분한다. 활동에서 쓴 답이 자동으로 개인 지식이 되지 않는다.
- 기본 개념 언어와 개인 표현은 함께 볼 수 있으며 개인 표현은 revision으로 변화할 수 있다.
- 학습 진행과 성취는 개인 지식의 표현 내용이나 연결 수를 하나의 점수로 환산하지 않는다.
- 학습 중에는 전체 지식 체계가 아니라 현재 페이지에 필요한 개념, 이번 챕터에서 바뀐 개인 지식과 가까운 인접 지식을 우선해서 보여 준다.

개인 지식의 소유권과 반영 규칙은 [[지식 체계/00 개인 지식화 원칙|개인 지식화 원칙]]을 따른다.

### 지식 책장의 세 가지 상태

지식을 학습에서 만났는지와 내 언어를 남겼는지는 서로 다른 상태다.

| 상태 | 기준 | 책장 표시 |
| --- | --- | --- |
| 아직 배우지 않음 | 해당 지식을 다루는 학습을 지나온 기록이나 내 표현·연결이 없다. | 잠금 아이콘, 비활성 |
| 배운 지식 | 해당 개념을 핵심·보조로 다루는 학습 페이지를 지나왔다. 응답 제출이나 정답은 필수가 아니다. | 책 아이콘, 활성 |
| 내 지식 | 활동에 내 언어로 이유·설명을 저장했거나, 개인 표현 또는 연결을 확인해 저장했다. | 사람 아이콘, 활성 |

‘내 지식’은 ‘배운 지식’보다 우선하여 표시한다. 단순 선택·자신감 표시·학습 전 예상만으로 ‘내 지식’이 되지는 않는다. Overview를 열거나 인접·선행·확장 링크로만 본 개념도 자동으로 배운 것으로 처리하지 않는다. 학습 페이지를 순서대로 지나면 해당 챕터에서 직접 다룬 지식이 활성화되며, 뒤로 돌아가거나 앱을 다시 실행해도 지나온 이력은 유지된다.

책장의 ‘내 지식’은 **내 설명이나 연결이 존재한다는 상태 표시**다. 활동 응답을 자동으로 개인 개념 revision에 반영하거나 확인 전 후보를 확정하는 동작이 아니다. 개인 표현의 정식 반영에는 기존 확인 절차를 유지하며, 어느 상태도 숙달 점수로 해석하지 않는다.

## 지도별 책임

- **학습 체계 지도**는 모든 Stage와 Chapter가 공유하는 학습·지식화·워크스페이스·콘텐츠 컴포넌트 계약을 소유한다.
- **Stage 지도**는 해당 Stage의 목적, 완료 기준, Chapter 순서와 Chapter 사이의 연결을 소유한다.
- **Chapter 지도**는 해당 Chapter의 목적, 완료 기준, 학습 경계, 페이지 순서와 페이지별 지식 연결을 소유한다.
- **학습 페이지**는 해당 페이지의 목표를 달성하기 위한 구체적인 설명, 활동, 응답과 완료 증거를 소유한다.

하위 지도와 페이지는 상위 계약을 반복해서 복사하지 않는다. 공통 계약을 바꿀 때에는 이 문서를 먼저 고치고, 특정 Stage·Chapter·페이지에만 해당하는 예외나 구체적인 선택만 하위 문서에 기록한다.

## 학습 콘텐츠 공통 계약

### 학습 경험 목표와 페이지 대구조

학습 페이지는 설명 블록을 끝까지 소비하게 하는 문서가 아니라, **지금 연습할 판단 하나를 의식하고 그 판단을 다른 상황에도 다시 사용하는 경험**을 만든다. 학습자는 페이지를 열었을 때 다음 네 가지를 빠르게 알 수 있어야 한다.

1. 이전 학습과 지금 판단이 어떻게 이어지는가?
2. 이번 페이지의 핵심 질문은 무엇인가?
3. 현재 나의 예상과 확신은 어떠한가?
4. 어떤 수행 증거가 있으면 이 페이지를 완료한 것인가?

모든 학습 페이지는 다음 대구조를 따른다.

```text
방향잡기: 연결·핵심 질문·첫 예상·완료 증거
→ 탐색: 설명 전 첫 시도·비교·피드백·개념 명명
→ 적용: 하나의 일관된 핵심 활동·판단 기준 설명
→ 학습 마무리: 첫 예상과 결과 비교·확신 조정·완료 증거·다음 사용 계획
```

- 핵심 활동에서 사용할 정의·예시·힌트는 활동과 가까이 놓고, 같은 내용을 독립 카드로 반복하지 않는다.
- 한 시점에 주요 작업 표면은 하나만 두고, 진행은 완료한 카드 수가 아니라 현재 판단 단계로 보여 준다.
- 심화 학습과 개인 지식화는 핵심 완료 흐름을 막지 않는 선택 영역에 둔다.
- 오답 피드백은 정답 단어만 제시하지 않고 놓친 판단 기준으로 돌아가게 한다.

### 의미 단위 조각으로 코드 읽기

**의미 단위 조각**은 코드에서 같은 판단, 책임, 데이터 흐름을 함께 설명하는 요소의 묶음이다. 꼭 이어진 줄이나 하나의 문장일 필요는 없다. 서로 떨어진 선언, 조건, 함수 호출도 한 결과를 만드는 같은 의미 흐름이라면 하나의 조각으로 읽을 수 있다.

사용자에게는 영문 용어 대신 “코드를 역할에 따라 의미 단위 조각으로 나누어 읽는다”라고 안내한다. 처음에는 뜻을 풀어 설명하고, 이후 질문·버튼·입력 안내에서는 문맥에 따라 “조각”, “조각 이름”, “조각 사이 흐름”으로 줄인다. 물리적으로 코드를 자르거나 연속된 줄만 고르는 활동으로 오해하지 않도록 떨어진 요소도 함께 선택할 수 있음을 알린다. 내부 Swift 타입·JSON 태그·저장 키에서는 `chunk`를 유지할 수 있지만 사용자 문구에는 노출하지 않는다.

학습자는 단어·문법·줄 단위 해석을 넘어 다음을 연습한다.

1. 코드가 담는 문제 상황과 결과를 먼저 예상한다.
2. 요소를 문법 모양이 아니라 역할과 책임으로 묶는다.
3. 떨어진 요소 사이의 데이터·판단·실행 흐름을 화살표로 연결한다.
4. 각 조각에 “이 코드가 무엇을 하는가”를 드러내는 이름을 붙인다.
5. 한 요소를 바꾸거나 제거했을 때 어느 조각과 결과가 달라지는지 설명한다.

각 Chapter는 주요 개념을 담은 코드를 의미 단위 조각으로 읽는 적용 기회를 두고, Stage 종료 시점에는 여러 Chapter의 조각을 연결해 하나의 문제 해결 흐름을 설명하게 한다.

### 지식 체계와 개인 지식화

각 학습 페이지는 지식을 소유하거나 복제하지 않고 현재 활동에 필요한 개념에 연결된다. 학습 화면에서는 전체 지식 지도를 펼쳐 놓지 않고 다음 지식 문맥을 우선해서 보여 준다.

1. 현재 페이지가 직접 사용하는 기본 개념
2. 현재 Chapter에서 내가 표현하거나 수정한 개념
3. 현재 개념과 연결된 가까운 인접 지식

활동에서 작성한 선택 이유, 자유 설명과 완료 증거는 먼저 학습 기록으로 저장한다. 그중 개념을 이해한 나만의 표현이나 새 연결로 남길 내용은 학습자가 확인한 뒤 개인 지식에 반영한다.

```text
기본 개념 사용
→ 활동 응답과 판단 설명
→ 개인 지식 반영 후보
→ 반영 여부와 내용 확인
→ 나의 개념 표현 또는 나의 관계로 저장
```

- 기본 개념명과 정의는 비교 기준으로 유지한다.
- 나만의 이름, 설명과 예시는 기본 개념에 겹쳐 저장한다.
- 나의 관계에는 연결한 개념, 연결 이유와 근거 활동을 남긴다.
- 개인 지식 반영 여부는 페이지 완료 조건과 분리한다.
- 개인 지식이 갱신되어도 학습 화면의 흐름과 입력 포커스를 빼앗지 않는다.

자세한 소유권과 변경 규칙은 [[지식 체계/00 개인 지식화 원칙|개인 지식화 원칙]]을 따른다.

### 학습 워크스페이스 콘텐츠 계약

학습 화면은 선형 학습을 진행하는 상세 영역과, 그 학습으로 해석되고 달라지는 지식을 보여 주는 문맥 사이드바로 나눈다.

- **상세 영역 최상단**은 이전 연결, 지금의 핵심 질문, 첫 예상과 확신, 완료 증거를 소유한다.
- **상세 영역 스크롤**은 현재 판단의 탐색, 핵심 활동, 피드백, 성찰과 이전·다음 이동을 소유한다.
- **문맥 사이드바**는 Stage·Chapter 메뉴나 두 번째 읽기 페이지가 아니다. 지금의 판단에 필요한 핵심 개념 하나와 보조 개념 최대 두 개를 우선한다.
- **inspector**는 기본적으로 지식을 읽고 비교하는 영역이다. 사용자가 `내 표현 편집`을 선택할 때만 입력 폼을 보이고, 관계 편집과 후보 검토는 각각 독립된 상태로 제공한다.
- `[지식 연결]`은 본문에서 활동과 기본 지식의 관계를 설명한다. `[지식 문맥]`은 같은 연결을 이용해 사이드바에 지금 필요한 범위만 계속 보여 준다.
- 사이드바에서 개념을 선택해도 학습 화면을 교체하지 않는다. 자세한 비교와 편집은 별도 inspector에서 열고, 닫으면 같은 학습 위치로 돌아온다.
- 학습 응답으로 만든 후보와 사용자가 확인해 저장한 개인 지식을 시각적으로 구분한다. 후보는 사이드바의 “달라진 지식”에 포함하지 않는다.
- 저장에 성공한 나의 표현과 연결은 현재 페이지를 유지한 채 사이드바에 갱신한다. 이 갱신은 키보드 입력 포커스를 옮기지 않는다.
- Focus Mode에서는 사이드바를 접을 수 있다. 접힌 동안에도 학습 기능과 자동 저장은 그대로 동작하며, 다시 열면 같은 지식 문맥을 복원한다.
- 보조 패널은 반응형으로 배치한다. 본문에 필요한 폭을 먼저 확보하고, 넓은 창에서는 사이드바·본문·인스펙터를 함께 보여 준다. 좁은 창에서는 본문을 유지한 채 사이드바와 인스펙터를 번갈아 보여 준다. 창을 넓히거나 인스펙터를 닫으면 사용자가 선택한 사이드바 상태를 복원한다.
- 자동 접힘은 사용자의 표시 선호를 변경하지 않는다. 크기 변경과 패널 전환으로 본문 스크롤·활동 입력을 초기화하지 않으며, 사용자는 툴바에서 원하는 보조 패널을 다시 열 수 있다. 구현 시 현재 최소 창 폭과 전환 경계 양쪽을 모두 검증한다.

사이드바의 기본 표시 순서는 다음과 같다.

1. **지금의 질문**: 현재 활동이 답하려는 질문 한 문장
2. **지금 쓰는 기준**: 핵심 개념 하나의 표준 정의 한 문장과 `이 활동에서는` 힌트
3. **함께 쓰는 개념**: 보조 개념 최대 두 개의 압축 행
4. **내가 바꾼 설명**: 확인한 개인 지식의 개수와 가장 최근 변화. 기본은 접힌 상태다.
5. **왜 이어지는가**: 인접 지식과 관계. 핵심 활동 완료 후 선택해 펼친다.

현재 페이지 제목과 요약, Focus Mode 설명은 사이드바에서 반복하지 않는다. 확인된 개인 지식이 없을 때에는 빈 목록 대신 “아직 확인해 반영한 나의 표현이나 연결이 없다”는 상태를 보여 준다.

## 콘텐츠 컴포넌트 문법

대괄호 안 이름은 페이지 제목이나 특정 사례의 이름이 아니라, 앱이 **어떤 방식으로 내용을 보여 주거나 어떤 상호작용을 제공할지** 나타내는 공용 컴포넌트다. 페이지마다 달라지는 내용은 컴포넌트 아래의 한국어 입력 항목에 넣는다.

### 읽기·관찰 컴포넌트

| 컴포넌트       | 역할                            | 주요 입력 항목                         |
| ---------- | ----------------------------- | -------------------------------- |
| `[학습 나침반]` | 페이지 시작에서 판단 방향과 메타인지 기준을 세운다. | 이전 연결, 핵심 질문, 첫 예상, 초기 확신, 완료 증거 |
| `[상황 제시]`  | 판단할 맥락과 자료를 제시한다.             | 제목, 상황, 자료, 첫 질문                 |

### 개인 지식 컴포넌트 상태

`[개인 지식 반영]`과 `[나의 연결 만들기]`는 다음 상태를 공통으로 가진다.

```text
학습 응답 저장
→ 개인 지식 후보 생성
→ 사용자가 내용 수정 또는 그대로 선택
→ 반영 확인
→ 개인 지식 저장
→ 사이드바 갱신
```

- 후보 생성 전과 생성 후 모두 원래 학습 응답은 학습 기록에 남는다.
- 확인 전 후보는 개인 지식으로 조회하거나 “달라진 지식”에 표시하지 않는다.
- 취소하면 후보만 닫고 학습 응답과 페이지 완료 상태는 유지한다.
- 기본 지식과 나의 표현 비교는 페이지 블록으로 반복하지 않는다. inspector의 기본 읽기 상태에서 나란히 보여 주고, 나의 이름·설명·예시만 명시적인 편집 상태에서 수정한다.
- 나의 연결은 출발·도착 개념뿐 아니라 관계 문장, 연결 이유와 근거 활동을 함께 저장한다.
- 개인 지식 편집은 사이드바 자체를 긴 입력 폼으로 만들지 않고 inspector에서 진행한다.

### 작성 규칙

1. `[주문 화면 미리보기]`처럼 한 사례에만 쓰이는 이름은 만들지 않는다. 같은 목적이라면 `[상황 제시]`에 주문 내용을 넣는다.
2. `[타입 소개 카드]`처럼 내용과 모양이 섞인 이름은 만들지 않는다. 비교 활동이면 `[개념 대조]`, 분류 활동이면 `[카드 분류]`를 쓴다.
3. 모든 입력 항목명은 `질문`, `카드`, `완료 조건`처럼 한국어로 기록한다.
4. Swift 식별자와 `String`, `Int`, `let` 같은 실제 코드 표기는 학습 대상이므로 코드 안에서는 원래 표기를 유지한다.
5. 현재 구현 범위의 선택 학습은 `더 깊게 가기` 하나만 두고, 별도 상태 선택 없이 핵심 완료 뒤 접힌 `[확장 과제]`로 제공한다.
6. `[개인 지식 반영]`은 활동 답안을 자동 저장하는 컴포넌트가 아니다. 학습 기록과 개인 지식을 구분하고 사용자가 반영을 확인한다.
7. 개인 지식 반영 여부는 페이지 완료 조건으로 사용하지 않는다.
8. `[지식 문맥]`의 “달라진 지식”에는 저장까지 완료된 개인 지식만 넣고 확인 전 후보는 별도로 표시한다.
9. `[나의 연결 만들기]`는 단순한 관련 링크가 아니라 학습자가 작성한 관계 문장과 이유를 요구한다.
10. 각 페이지는 `[지식 연결]`과 `[지식 문맥]`을 함께 정의하되, 본문과 사이드바에 같은 설명을 중복 노출하지 않는다.
11. 각 lesson 페이지는 `방향잡기 → 탐색 → 적용 → 학습 마무리`의 순서를 유지하고, 설명 전에 최소 한 번의 첫 예상이나 선택을 둔다. Chapter Overview는 아직 수행 뒤가 아니므로 나침반의 초기 기록까지만 남긴다.
12. 성찰에서는 확신 수치 자체를 점수화하지 않고, 판단이 바뀐 것을 설명할 수 있는지를 본다.
13. 의미 단위 조각은 줄 위치로만 묶지 않고 같은 결과·책임에 기여하는 떨어진 요소를 포함할 수 있게 작성한다.
14. `[학습 나침반]`이 이전 연결을 소유하므로 별도의 회상 컴포넌트를 앞에 반복하지 않는다.
15. `[학습 마무리]`가 성찰과 완료 판단을 함께 소유하며, 같은 lesson에서 두 블록으로 다시 나누지 않는다.

## 새 Chapter 생성 계약

새 Chapter는 페이지 목록이나 컴포넌트 조합부터 만들지 않는다. **Stage에서 맡을 변화 → 화면 전체 경험 → 영역의 역할 → 페이지 경로 → 블록의 역할 → 블록 내부 → 사이드바·inspector → 데이터와 구현** 순서로 큰 결정이 작은 결정을 제한하게 만든다.

### 1. Stage 안에서 맡을 변화를 먼저 정한다

Chapter 지도에 다음을 먼저 기록한다.

1. 이전 Chapter가 만든 결과물은 무엇인가?
2. 이번 Chapter가 새로 연습할 핵심 사고 행동은 무엇인가?
3. 다음 Chapter가 입력으로 사용할 결과물은 무엇인가?
4. 이번 Chapter에서 다루지 않을 경계는 무엇인가?
5. 처음 보는 문제에서 어떤 수행 증거를 만들면 완료인가?

Chapter의 목표는 개념 목록이 아니라 **학습자가 전과 다르게 할 수 있게 되는 판단과 행동**으로 쓴다. 페이지 수는 이 변화를 만드는 데 필요한 판단 단계에서 도출하며 고정된 숫자에 맞추지 않는다.

### 2. 화면 전체와 영역의 역할을 정한다

페이지를 쓰기 전에 해당 Chapter의 학습 경험 설계 문서에서 다음 순서로 현재 경험과 개선할 경험을 대조한다.

1. 사이드바와 메인 페이지 최상단이 함께 보일 때 학습자가 가장 먼저 알아야 할 것
2. 메인 페이지 최상단, 스크롤 본문, 사이드바와 inspector가 각각 소유할 역할
3. Overview부터 마지막 페이지까지 각 페이지가 맡을 판단과 전이
4. 각 페이지에서 사용할 블록의 순서와 블록마다 만들 응답
5. 각 블록 내부에서 먼저 보일 정보, 조작, 피드백과 완료 상태
6. 메인 흐름을 돕기 위해 사이드바가 계속 보여 줄 질문·기준·보조 지식

이 순서를 거꾸로 진행하지 않는다. 작은 UI 선택이 상위 경험 목표와 충돌하면 작은 선택을 바꾼다.

### 3. 페이지 경로를 하나의 사고 진행으로 만든다

Overview는 이전 결과물, 이번 Chapter의 핵심 질문, 전체 판단 경로와 최종 수행 증거를 예고한다. 각 lesson은 한 가지 재사용 가능한 판단을 맡고, 앞 페이지의 결과를 다음 페이지의 입력으로 사용한다.

```text
Overview: 이전 결과와 이번 핵심 질문 연결
→ 발견: 설명 전에 차이를 예상하고 첫 판단 남기기
→ 명명: 시도에서 발견한 기준과 개념을 짧게 이름 붙이기
→ 적용: 새로운 사례에서 같은 판단을 근거와 함께 다시 사용하기
→ 전이: 도움을 줄인 처음 보는 문제에 적용하기
→ 의미 단위 조각 읽기: Chapter의 주요 개념이 만드는 역할·책임·흐름·변경 영향을 묶어 설명하기
```

Stage 1의 각 Chapter는 마지막 lesson을 **의미 단위 조각 읽기 통합 페이지**로 둔다. 이 페이지는 앞선 lesson을 단순히 다시 묻지 않고, 서로 떨어진 코드 요소를 선택해 다음 증거를 만든다.

- 문제 상황과 예상 결과
- 역할이나 책임을 공유하는 요소의 묶음과 그 경계
- 각 조각의 의미 이름
- 조각 사이의 데이터·판단·실행 흐름
- 한 요소가 바뀌거나 사라질 때 달라지는 조각과 결과
- 다음 Chapter에서 이 조각이 맡게 될 입력 또는 책임

### 4. lesson의 공통 뼈대를 채운다

각 lesson은 다음 질문에 답하는 순서로 구성한다.

| 구간 | 작성 질문 | 기본 컴포넌트 |
| --- | --- | --- |
| 방향잡기 | 무엇과 이어지고, 지금 어떤 질문에 답하며, 처음에는 어떻게 예상하는가? | `[학습 나침반]` |
| 탐색 | 정답 설명 전에 어떤 자료를 보고 차이를 선택·분류·예측하는가? | `[상황 제시]`와 작업 컴포넌트 |
| 기준 발견 | 첫 시도에서 놓치기 쉬운 차이와 다른 문제에도 쓸 판단 질문은 무엇인가? | `[개념 대조]`, `[개념 정의]`, `[판단 기준]`, `[코드 해설]`, `[과정 안내]` |
| 핵심 적용 | 한 과제 안에서 무엇을 조작하고 어떤 근거를 설명해야 하는가? | 목표에 맞는 사용자 작업 컴포넌트 하나를 중심으로 구성 |
| 마무리 | 첫 예상이 어떻게 바뀌었고, 어떤 증거가 있으며, 어디서 다시 쓸 것인가? | `[학습 마무리]` |
| 선택 확장 | 핵심 완료를 방해하지 않고 무엇을 더 탐색하거나 개인 지식으로 남길 수 있는가? | `[확장 과제]`, 개인 지식 컴포넌트 |

읽기 블록의 개수나 활동 수를 맞추지 않는다. 같은 판단을 반복하는 블록은 합치고, 핵심 적용과 직접 관계없는 내용은 확장 과제나 지식 노트로 보낸다.

### 5. 지식 문맥을 페이지와 함께 설계한다

페이지마다 다음 세 범위를 선언한다.

1. **핵심 개념 하나**: 이번 판단의 기준이 되는 개념
2. **보조 개념 최대 두 개**: 핵심 과제를 수행할 때 함께 쓰는 개념
3. **가까운 지식**: 완료 뒤 연결 이유를 탐색할 때만 필요한 개념

본문의 `[지식 연결]`은 “이 지식이 이번 판단에서 어떻게 쓰이는가”를 설명하고, 사이드바는 같은 내용을 다시 길게 쓰지 않는다. 개인 지식 후보는 근거 활동과 연결하고, 저장 확인 전에는 확인된 변화로 취급하지 않는다.

### 5-1. 지식 노트의 다시 보기를 한곳에 모은다

각 지식 노트는 학습 페이지 역참조를 **`## 다시 보기` 섹션 하나**에 모은다. Chapter별 다시 보기나 “이 지식을 사용하는 학습 페이지” 같은 별도 섹션을 추가하지 않는다.

- 현재 앱에 포함된 모든 Chapter에서 이 지식을 핵심·보조·선행·확장으로 직접 사용하는 페이지와, 완료 뒤 가까운 지식으로 연결해서 볼 페이지를 찾는다.
- 같은 지식과 페이지가 직접 사용과 가까운 지식에 모두 있으면 직접 사용 하나만 남긴다.
- `Stage → Chapter 순서 → Overview와 lesson 순서 → stable page ID` 순으로 정렬하고, 페이지 링크 옆에는 이 지식이 쓰이는 이유를 한 문장으로 적는다.
- 연결된 앱 페이지가 아직 없더라도 `다시 보기` 섹션은 유지하고, 이후 페이지가 생길 때 추가한다.
- Knowledge Catalog JSON의 `revisitPages`에는 같은 `chapterID`, `pageID`, 제목, 순서, 직접 사용·가까운 지식 구분과 연결 이유를 기록한다.
- SwiftUI 지식 상세는 JSON 순서대로 목록을 보여 주고 선택하면 해당 학습 페이지를 연다. 링크를 보거나 이동하는 일만으로 `배운 지식`이나 `내 지식` 상태를 만들지 않는다.
- 새 Chapter를 작성할 때에는 새 페이지에 연결한 지식뿐 아니라 기존 Chapter의 학습이 새 지식으로 이어지는 곳도 함께 확인한다. 관련된 모든 지식 노트의 기존 `다시 보기`를 갱신하고, 중복·누락·깨진 stable ID를 검증한다.

### 6. Markdown을 데이터와 SwiftUI로 승격한다

원본은 Obsidian Markdown이다. JSON과 SwiftUI는 원본의 의미를 임의로 다시 설계하지 않고 다음 순서로 승격한다.

```text
Stage 지도와 Chapter 지도
→ Chapter 학습 경험 설계
→ Overview와 lesson Markdown
→ 필요한 지식 노트와 관계
→ Chapter JSON과 Knowledge Catalog JSON
→ content identity manifest
→ 공용 schema·validator·renderer
→ 접근성·좁은 창·자동 저장·콘텐츠 계약 테스트
```

- 새 페이지 수, 마지막 페이지, 이전·다음 이동은 배열 위치나 고정 숫자가 아니라 stable ID와 navigation metadata에서 읽는다.
- Chapter마다 새 SwiftUI 화면을 만들지 않고 공용 section tag와 renderer를 조합한다.
- 새 상호작용이 기존 컴포넌트의 역할과 같으면 공용 컴포넌트를 확장하고, 의미와 응답 구조가 다를 때만 새 tag를 만든다.
- 기본 macOS 입력 컨트롤이 선택지와 현재 상태를 동시에 이해하기 어렵게 만들면, 학습 블록 안에서는 내용·선택·피드백을 한 표면에 보여 주는 공용 커스텀 컨트롤을 사용한다.
- 활동 응답, 개인 지식 후보, 확인해 저장한 개인 지식의 상태와 저장 시점을 섞지 않는다.

### 7. Chapter 완료 점검

다음이 모두 참일 때 새 Chapter가 이 학습 체계에 들어올 수 있다.

- Chapter의 목표가 개념 나열이 아니라 사고 행동의 변화로 쓰였다.
- 이전 Chapter의 결과가 첫 페이지의 입력이 되고 마지막 결과가 다음 Chapter로 이어진다.
- Overview와 모든 lesson에서 핵심 질문과 완료 증거를 찾을 수 있다.
- 각 lesson은 `방향잡기 → 탐색 → 적용 → 학습 마무리`의 순서를 지킨다.
- 설명 전 첫 시도와 처음 보는 문제에 대한 전이 활동이 있다.
- 마지막 lesson에서 주요 개념을 비연속적인 의미 단위 조각으로 묶고 흐름과 변경 영향을 설명한다.
- 사이드바는 질문, 핵심 하나, 보조 최대 두 개를 우선하며 메인 페이지를 반복하지 않는다.
- inspector를 열거나 개인 지식을 저장하지 않아도 lesson을 완료할 수 있다.
- Markdown, JSON, 지식 catalog와 identity manifest의 stable ID와 링크가 일치한다.
- 지원하는 모든 section tag가 decode·validate·render되고 키보드와 VoiceOver 경로가 있다.
- 좁은 창에서는 보조 패널을 번갈아 표시해 본문을 보존하고, 넓은 창에서 둘을 함께 표시해도 주요 콘텐츠가 잘리지 않는다. 크기 변경 후에도 학습 위치와 사용자의 표시 선호가 유지된다.
- 페이지 수를 바꿔도 홈 진행률, 이어하기, 이전·다음 이동과 Chapter 완료가 동작한다.
