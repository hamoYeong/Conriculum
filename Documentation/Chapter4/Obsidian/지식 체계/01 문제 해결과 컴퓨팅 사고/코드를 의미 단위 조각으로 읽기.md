# 코드를 의미 단위 조각으로 읽기

## 한 문장 정의

의미 단위 조각으로 코드를 읽기는 문법이나 줄 위치보다 같은 대상·책임·데이터·판단·실행 흐름에 기여하는 요소를 하나의 의미 단위로 묶는 코드 읽기 전략이다. ^semantic-chunk-reading-definition

## 구분 질문

“이 요소들은 붙어 있거나 문법이 같아서가 아니라, 함께 무엇을 설명하고 만드는가?”

## 판단 순서와 기준

1. 코드 전체가 다루는 문제 상황과 예상 결과를 먼저 말한다.
2. 각 요소가 담는 데이터·판단·실행 역할을 표시한다.
3. 떨어진 요소도 같은 결과에 기여하면 연결한다.
4. 조각의 책임을 동사가 포함된 한 문장으로 이름 붙인다.
5. 한 요소를 바꿀 때 어느 조각과 결과가 달라지는지 예측한다.

## 대표 예시와 경계

`capacity`, `attendeeCount`, `isPaid`가 서로 떨어져 선언되어 있어도 신청 가능 여부를 판단하는 다음 흐름의 재료라면 `신청 판단을 준비한다`는 조각으로 읽을 수 있다. 반면 `accentColorName`은 화면 스타일을 설명하므로 같은 `String`이라도 그 조각에 포함하지 않는다.

조각 경계는 하나의 절대적 정답이 아니다. 읽는 목적과 문제 경계에 따라 달라질 수 있으며, 요소를 포함·제외한 근거를 설명해야 한다.

## 오해와 교정

- 연속된 코드 줄을 그대로 조각으로 부른다. → 줄 간격보다 같은 책임과 결과를 확인한다.
- 같은 타입이나 문법을 쓴 요소끼리 묶는다. → 타입이 달라도 같은 사례와 결과에 기여하면 함께 읽는다.
- 모범 조각 이름과 경계를 외운다. → 자신의 묶음으로 실행 흐름과 변경 영향을 설명할 수 있는지 확인한다.
