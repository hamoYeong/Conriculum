# 식별자와 이름 짓기

## 한 문장 정의

식별자는 코드에서 값을 가리키는 이름이며, 좋은 이름은 값의 대상·역할·단위를 읽는 사람에게 드러낸다.

## 구분 질문

이 이름만 보고도 값이 무엇이며 어디에 쓰이는지 구분할 수 있는가?

## 판단 순서와 기준

- `data`, `value`, `number`보다 구체적인 대상과 역할이 드러나는가?
- 비슷한 값과 구별할 맥락이나 단위가 필요한가?
- Bool 이름이 참일 때 질문과 답처럼 자연스럽게 읽히는가?
- Swift의 lowerCamelCase 관례를 따르는가?

## 대표 예시와 경계

`20_000`에 `value`보다 `orderAmount`라는 이름을 붙이면 주문 금액이라는 역할이 드러난다. `isPaid`는 “결제되었는가?”라는 질문처럼 읽힌다.

## 오해와 교정

- 오해: 짧은 이름이 항상 읽기 좋다. → 교정: 사용하는 범위에서 대상과 역할을 구분할 만큼 구체적으로 짓는다.
- 오해: 타입 이름을 반복하면 의미가 충분하다. → 교정: `userString`보다 `userNickname`처럼 문제 속 역할을 드러낸다.
- 오해: 코드가 실행되기만 하면 이름은 중요하지 않다. → 교정: 이름은 여러 선언을 의미 단위 조각으로 읽고 변경 영향을 추적하는 단서다.

## 유형이 있는 지식 관계

- 선언 대상: 식별자는 [[지식 체계/02 값과 타입/상수와 변수|상수나 변수]]를 가리킨다.
- 읽기 단서: 관련된 여러 값의 이름은 [[지식 체계/02 값과 타입/관련된 값 묶기|한 사례의 역할]]과 경계를 드러낸다.
- 확장: 같은 원리는 이후 함수와 타입의 이름으로 이어진다.
