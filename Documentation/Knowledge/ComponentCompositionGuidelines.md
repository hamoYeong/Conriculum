# 정보 컴포넌트 구성 기준

지식 화면과 학습 화면의 컴포넌트 경계는 둥근 사각형이 아니라 정보의 의미,
반복 방식, 상호작용 책임으로 정한다. 같은 데이터 구조가 여러 화면에 나타나거나
하나의 접근성 의미 단위를 이루면 컴포넌트로 분리한다.

## 시각 위계 적용 순서

정보를 구분할 때는 다음 순서로 필요한 만큼만 사용한다.

1. 제목과 본문의 글꼴 위계
2. 행동 분류를 나타내는 공통 아이콘과 색, 정렬과 들여쓰기
3. 항목 사이 간격과 구분선
4. 핵심 질문이나 상태를 나타내는 짧은 수평 표식 또는 옅은 색면
5. 독립된 표면

앞 단계만으로 의미가 충분히 전달되면 다음 단계로 넘어가지 않는다.

## 표면을 사용하는 경우

- 별도로 선택하거나 이동할 수 있는 카드와 그래프 노드
- 저장·취소처럼 독립된 작업 상태를 갖는 편집 또는 검토 영역
- 오류, 경고, 저장 상태처럼 주변 흐름에서 즉시 분리해야 하는 피드백
- 상황, 핵심 개념, 판단 기준처럼 읽다가 한 번 멈추어 받아들여야 하는 인지적
  체크포인트
- 홈 대시보드처럼 여러 정보를 묶는 최상위 요약 패널

텍스트 필드와 편집기의 시스템 테두리는 입력 가능성을 알리는 조작 단서이므로
표면 중첩으로 보지 않는다.

## 표면을 사용하지 않는 경우

- 섹션 제목 아래에 이어지는 설명과 목록
- 같은 종류의 관계, 예시, 질문이 반복되는 행
- 이미 표면 안에 들어간 요약 항목과 빈 상태
- 색이나 배경 없이도 제목과 간격으로 구분되는 읽기 전용 정보

하나의 표면 안에 다른 정보 표면을 중첩하지 않는다. 자식 컴포넌트는 기본적으로
평면 표현을 사용하고, 자식이 독립된 상호작용 책임을 가질 때만 예외로 한다.

## 공용 컴포넌트 역할

- `KnowledgeSection`: 제목과 내용을 묶는 의미 섹션. 기본값은 `plain`이다.
- `KnowledgeDefinitionBlock`: 변경되지 않는 개념 한줄 설명.
- `KnowledgeQuestionBlock`: 반복해서 돌아볼 핵심 질문과 선형 강조.
- `KnowledgeItemList`: 판단 질문, 기본 예시, 오해를 marker와 간격으로 구분한다.
- `KnowledgeLabeledText`: 짧은 라벨과 단일 본문을 묶는다.
- `KnowledgeMessageBanner`: 주변 흐름과 분리해야 하는 상태 피드백만 담당한다.

화면 Feature는 데이터와 상호작용을 공급하고, 이 컴포넌트들은 Store나 화면
라우팅을 소유하지 않는다. 읽기 전용 지식 표현은 Inspector와 전역 지식 체계가
공유하고, 편집 상태와 저장 동작은 각 Feature가 유지한다.

## 학습 컴포넌트 역할

- `LearningBlock(role: .flow)`: 기본 역할이다. 기억 연결, 비교, 코드 설명처럼
  앞뒤 흐름을 이어 읽는 내용을 배경 없는 의미 섹션으로 구성한다. 다른 역할과
  동일한 20pt 콘텐츠 인셋을 사용해 제목과 본문의 정렬 기준을 맞춘다.
- `LearningBlock(role: .checkpoint)`: 상황, 핵심 개념, 판단 기준처럼 읽다가
  멈춰 생각하거나 기억해야 하는 내용에 하나의 절제된 표면을 제공한다.
- `LearningBlock(role: .task)`: 입력, 선택, 저장 상태를 함께 소유하는 독립
  과제에 하나의 최상위 작업 표면을 제공한다.
- `LearningBlock(role: .feedback)`: 콘텐츠 연결 오류처럼 주변 흐름과 즉시
  분리해야 하는 피드백을 나타낸다.
- `LearningIntent`: 회상, 맥락 파악, 관찰, 기억, 판단, 적용, 성찰, 피드백을
  같은 SF Symbol과 색으로 반복해 학습 행동의 길잡이를 제공한다. 콘텐츠 JSON에는
  추가하지 않고 SwiftUI 표현 계층에서만 사용한다.
- `LearningSupportLabel`: 평면형 하위 정보의 시작을 짧은 수평 표식과 라벨로
  나타낸다. 모든 항목에 아이콘이나 세로선을 반복하지 않는다.
- `LearningCallout`: 기본적으로 평면이며, 기억할 문장이나 관찰 질문처럼 잠시
  멈춰야 하는 내용에만 `emphasized` 색면을 사용한다.
- `LearningLabeledTextGrid`, `ActivityCriteriaView`: 의미와 접근성 단위는
  유지하되 자체 배경 표면은 만들지 않는다.

활동 표면 안에서도 선택 카드와 드롭 영역은 독립 조작 대상이므로 경계를 유지할
수 있다. 코드 영역과 시스템 입력 테두리도 읽기·입력 가능성을 알리는 조작 단서로
유지한다. 그 외의 설명, 완료 기준, 비교 예시와 반복 행은 글꼴 위계, 간격,
짧은 수평 표식이나 필요한 구분선으로 나눈다. 아이콘과 색은 장식이 아니라
사용자가 수행할 행동 분류를 나타낼 때 일관되게 반복한다.
