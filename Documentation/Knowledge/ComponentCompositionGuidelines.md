# 지식 컴포넌트 구성 기준

지식 화면의 컴포넌트 경계는 둥근 사각형이 아니라 정보의 의미, 반복 방식,
상호작용 책임으로 정한다. 같은 데이터 구조가 여러 화면에 나타나거나 하나의
접근성 의미 단위를 이루면 컴포넌트로 분리한다.

## 시각 위계 적용 순서

정보를 구분할 때는 다음 순서로 필요한 만큼만 사용한다.

1. 제목과 본문의 글꼴 위계
2. 아이콘, 색, 정렬과 들여쓰기
3. 항목 사이 간격과 구분선
4. 핵심 질문이나 상태를 나타내는 짧은 선형 강조
5. 독립된 표면

앞 단계만으로 의미가 충분히 전달되면 다음 단계로 넘어가지 않는다.

## 표면을 사용하는 경우

- 별도로 선택하거나 이동할 수 있는 카드와 그래프 노드
- 저장·취소처럼 독립된 작업 상태를 갖는 편집 또는 검토 영역
- 오류, 경고, 저장 상태처럼 주변 흐름에서 즉시 분리해야 하는 피드백
- 홈 대시보드처럼 여러 정보를 묶는 최상위 요약 패널

텍스트 필드와 편집기의 시스템 테두리는 입력 가능성을 알리는 조작 단서이므로
표면 중첩으로 보지 않는다.

## 표면을 사용하지 않는 경우

- 섹션 제목 아래에 이어지는 설명과 목록
- 같은 종류의 관계, 예시, 질문이 반복되는 행
- 이미 표면 안에 들어간 요약 항목과 빈 상태
- 색이나 배경 없이도 제목과 간격으로 구분되는 읽기 전용 정보

하나의 표면 안에 다른 정보 표면을 중첩하지 않는다. 자식 컴포넌트는 기본적으로
평면 표현을 사용하고, 자식이 독립된 상호작용 책임을 가질 때만 예외로 한다.

## 공용 컴포넌트 역할

- `KnowledgeSection`: 제목과 내용을 묶는 의미 섹션. 기본값은 `plain`이다.
- `KnowledgeDefinitionBlock`: 변경되지 않는 개념 한줄 설명.
- `KnowledgeQuestionBlock`: 반복해서 돌아볼 핵심 질문과 선형 강조.
- `KnowledgeItemList`: 판단 질문, 기본 예시, 오해를 marker와 간격으로 구분한다.
- `KnowledgeLabeledText`: 짧은 라벨과 단일 본문을 묶는다.
- `KnowledgeMessageBanner`: 주변 흐름과 분리해야 하는 상태 피드백만 담당한다.

화면 Feature는 데이터와 상호작용을 공급하고, 이 컴포넌트들은 Store나 화면
라우팅을 소유하지 않는다. 읽기 전용 지식 표현은 Inspector와 전역 지식 체계가
공유하고, 편집 상태와 저장 동작은 각 Feature가 유지한다.
