# SwiftData 저장 항목과 화면에서 사용하는 기준

확인 기준: 2026-09-04, 현재 앱 소스의 모델·저장 호출 경로. 사용자의 DB를 열어 실제 건수를 조사한 문서는 아니다.

## 실제로 저장되는 사용자 데이터

| 분류 | 모델 | 저장 내용 | 현재 저장 시점과 갱신 방식 |
| --- | --- | --- | --- |
| 로컬 사용자 | `LocalProfileRecord` | 사용자 ID, 생성 시각, 마지막 열림 시각 | 저장소가 프로필을 처음 조회할 때 생성하거나 마지막 열림 시각을 갱신. 이후 같은 저장소 인스턴스에서는 ID를 캐시한다. |
| 학습 위치 | `LearningProgressRecord` | 사용자·챕터 ID, 현재 페이지 ID, 완료 페이지 ID 목록, 갱신 시각 | 페이지 이동·완료 요약 이동·다음 챕터 진입 때 저장. 사용자 × 챕터마다 한 행을 갱신한다. |
| 활동 응답 | `ActivityResponseRecord` | 응답·활동·페이지·사용자 ID, 입력 필드의 키와 문자열 배열, 기록 시각 | 입력 후 750ms 자동 저장, 재시도, 페이지 이동 전에 저장. 같은 응답 ID는 갱신한다. 필드 묶음은 JSON Data로 보관한다. |
| 나의 지식 표현 | `PersonalConceptRevisionRecord` | 개념 ID, 나만의 이름, 설명, 예시 배열, 이전 revision ID, 근거 활동 ID, 생성 시각 | 인스펙터에서 확인하여 저장할 때 새 revision을 만들고 이전 revision과 연결한다. 예시는 JSON Data로 보관한다. 기본 개념은 덮어쓰지 않는다. |
| 나의 지식 관계 | `PersonalKnowledgeRelationRecord` | 출발·도착 개념 ID, 관계 설명, 이유, 근거 활동 ID, 생성 시각, 사용자 ID | 개인 관계를 확인하여 저장. 수정은 같은 관계 ID의 값을 갱신한다. 기본 지식 관계와 분리된다. |
| 학습 열람 | `LearningEvidenceRecord`의 `viewed` | 사용자·페이지 ID, 열람 시각, 과거 진도에서 복원했는지 나타내는 메모 | lesson 표시 시 자동 저장. 같은 페이지는 중복 생성하지 않으며, 뒤로 돌아가도 이력을 유지한다. 이동 전에도 기록을 보존한다. |

입력값은 활동마다 다르다. 선택한 카드·짝·코드 조립 순서, 빈칸, 자유 서술, 판단 이유, 학습 전 예상, 마무리 자기 점검, 의미 단위 조각 읽기 응답 등이 `ActivityResponseRecord.fieldsPayload`에 들어간다. 정답 여부나 숙달을 자동으로 보증하는 기록은 아니다.

## 모델은 있지만 자동 기록은 아직 연결되지 않은 항목

`LearningEvidenceRecord`의 **열람(`viewed`)은 이제 `recordPageVisit`을 통해 자동 기록된다.** 나머지 활동 시도·도움으로 성공·독립 성공·판단 설명·개념 연결은 저장 가능한 모델과 API만 있으며, 자동 생성은 아직 연결하지 않았다. 활동 응답을 저장했다고 별도의 성공·판단 증거가 생기는 것은 아니다.

`LearningProgressRecord.completedPageIDs` 역시 저장 필드는 있지만 현재 페이지 이동 로직은 기존 집합을 보존할 뿐 새 완료 항목을 추가하지 않는다. 마지막 페이지에 도착하거나 완료 요약을 연 것을 ‘모든 활동 완료’ 또는 ‘숙달’로 해석하면 안 된다.

## 책장의 세 가지 상태

| 상태 | 판정 | 표시 |
| --- | --- | --- |
| 아직 배우지 않음 | 학습에서 만난 기록도 개인 표현·연결도 없음 | 잠금 아이콘, 비활성 |
| 배운 지식 | 해당 개념을 핵심·보조로 다루는 lesson을 지나옴. 응답 저장은 필수가 아님 | 책 아이콘, 활성 |
| 내 지식 | 저장한 활동에 내 설명이 있거나, 확인해 저장한 개인 표현 또는 개인 관계의 한쪽 개념 | 사람 아이콘과 보라색 상태 표시, 활성 |

‘내 지식’이 ‘배운 지식’보다 우선한다. 내 설명에는 분류·짝짓기·선택의 이유, 자유 서술, 회상 답변, 마무리 설명·기준·다음 사용, 의미 단위 조각의 이름·흐름·경계·변화 설명이 포함된다. 개인화 활동은 선택한 대상 개념으로 범위를 한정하고, 제공된 기본 문구만 저장된 경우는 제외한다. 단순 선택 ID, 코드 조립·빈칸, 자신감 선택, 학습 전 예상만으로는 ‘내 지식’으로 올리지 않는다. 판정에는 활동별 최신 저장 응답을 사용한다.

Overview를 열거나 주변·선행·확장 링크를 보는 것만으로 챕터의 모든 지식을 활성화하지 않는다. 한 챕터를 순서대로 지나면 각 페이지에서 다룬 지식이 활성화된다. 정답·독립 해결·숙달 판정과는 별개다.

기존 버전은 페이지별 방문 이력이 없으므로, 저장된 진도의 현재 페이지까지와 기존 완료 페이지를 지나온 것으로 복원한다. 저장된 유효 활동 응답도 해당 페이지를 만난 근거로 사용한다. 이후 해당 챕터를 열거나 이동할 때 복원한 페이지를 기존 `viewed` 모델에 보존하므로, 이전 페이지로 돌아가도 지식이 다시 잠기지 않는다. 복원 기록의 시각은 과거의 실제 방문 시각이 아니라 복원 시각이다.

새 필드나 SwiftData 스키마 변경은 없다. 기존 데이터는 유지하고 열람 행만 추가한다. 화면 상태는 열람·진도·응답·개인 지식과 JSON으로 계산하며 별도의 `isLearned` 플래그를 중복 저장하지 않는다.

## SwiftData에 저장하지 않는 것

- 기본 챕터·페이지·학습 블록·개념·기본 관계: 앱 번들의 JSON 콘텐츠.
- 옵시디언 원문: 별도의 Markdown 파일.
- 현재 선택한 책장 분류·검색어·상세/비교 개념, 사이드바 표시·인스펙터 표시·집중 모드, 스크롤 위치: 실행 중 UI 상태.
- 인스펙터에 확인 반영하기 전의 개인화 후보: 실행 중 상태. 관련 활동의 입력 응답이 저장될 수 있는 것과는 별개다.
- 저장 실패·검증 오류·자동 저장 대기 중의 입력: 메모리 상태이므로 저장 성공 전 종료하면 보존을 보장하지 않는다.
- 홈의 요약·챕터 목록·최근 기록 표시, 책장의 관계 색상: 콘텐츠와 저장 기록을 조합한 화면용 값.

## 저장 범위

실제 앱은 디스크 기반 SwiftData 컨테이너를 사용한다. `cloudKitDatabase: .none`이므로 iCloud/CloudKit 동기화는 설정돼 있지 않다. Preview와 테스트는 별도의 메모리 컨테이너를 사용한다. 옵시디언 보관함의 iCloud 동기화와 앱의 사용자 학습 기록 저장은 서로 다른 체계다.

모델 등록: `Conriculum/Persistence/PersistenceContainerFactory.swift`.
저장 구현: `Conriculum/Persistence/Stores/UserDataStore.swift`.
학습 상태 판정: `Conriculum/Features/KnowledgeSystem/LearnedKnowledgeResolver.swift`.
